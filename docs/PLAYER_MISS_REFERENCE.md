# 自机受击掉落与持续消弹

源证据为本机《东方红魔乡：新典》`th06nc.exe`，SHA-256 为
`48630a42a2eb6762d0db2a7e0d151203efbe67220fef7d2f9d0d51857928ac82`。
以下地址均为 RVA，帧数按 60 Hz 解释。结论来自静态控制流审阅，未代替原程序逐帧实测。
`tools/inspect_native_rank_events.py` 已验证同一文件身份及其中的自机事件更新代码区间。

## 掉落

`0x6a20d…0x6a22a` 在 Miss 确认倒计时归零后结算。`0x6a237…0x6a24b`
检查扣命前额外残机库存：正数时，`0x6a251…0x6a29a` 请求一件 item 2 和五件 item 0；
零或负数时，`0x6a3ce…0x6a418` 请求五件 item 4。分别对应大 P（8）、小 P（1）和满 P。
全部使用 drop_state 2，数量与当前 Power 无关，满火力时也不转换成分数道具。
实际扣库存晚于此判断，不能用扣命后库存选择配方。池满可使请求失败。

`0x6a230` 借用受击位置；项目在 `Player::TakeHit` 重置姿态之前保存该位置并生成道具。
原生 `0x440aa…0x441b1` 为每件道具依次读取随机横纵目标，范围为 x=[48,336)、
y=[-64,128)，随后 `0x443f4…0x44467` 用 60 帧散落到前方，再切入下落。

三维适配保持受击世界 Y 高度，以战场半长表达随机区域：X 为 ±0.75 倍横向半长，
Z 为 [3/7,9/7) 倍纵向半长。出生位置和随机目标由单件道具独占，不依赖相机。
项目散落期间不能拾取或追踪；这是配合即时复活的保护适配，防止出生点附近立刻吃回全部掉落。
原生 `0x443d9…0x443ee` 的自动吸取可打断散落，`0x44577` 以后仍检查拾取，实际由
死亡/重生中的自机状态门槛阻止拾取，并非道具自带一秒保护。
项目散落结束后从零下落速度接入现有道具运动，保留 Bomb 已设置的吸取标记。
项目以连续一秒插值并抵达目标，替代原生 n=0…59 的离散插值及第 60 帧不补齐目标的细节；
跨更新边界只将剩余时间交给下落或吸取，不额外消耗一帧。

## 消弹

`0x6a635` 在重生状态每次写入 90 帧清弹计数；`0x6a2f6…0x6a30d`
先递减，再执行本次清池，因此 1→0 的末次仍清弹。按死亡状态计时控制流推导，
重生段连续刷新 31 次，此后消费剩余 89 次，共 120 次清池（两秒）。
原生碰撞后另有 8 帧 Miss 确认等待和死亡等待，清池并非在碰撞瞬间启动。

`0x6a320…0x6a33c` 扫描普通弹池并进入消散状态，`0x6a350…0x6a37c`
使活动光束退出。没有位置/距离过滤，也不创建星点或计分奖励；自机弹不在这些敌方池中。

项目沿用即时确认 Miss、即时复活的既有流程，从确认 Miss 时立即清池并持续两秒。
普通弹和光束直接删除，未移植原生消散动画；没有把两秒消弹当成全部复活无敌时间。
`BulletSystem::Update` 在本步演员交付新弹后执行持续清池，再消费时间，保证末步有效；
暂停不更新，世界时停冻结窗口，`Reset` 取消窗口，普通瞬时清弹不会提前取消或重新延长它。
末命仍请求原生满 P 配方，但项目当前 GameOver 会清理场上道具，没有新增续关流程。

## 验证

`tests/drop_tests.cpp` 独立核对六件/五件配方、受击点、散落保护、随机目标、不同更新频率及跨边界下落。
`tests/gameplay_tests.cpp` 核对持续清弹的普通弹/光束、自机弹保留、尾步、到期放行、暂停等效零步长、
时停和重置。`tests/lifecycle_tests.cpp --player-miss-only` 通过正式碰撞和 Game 固定步验证
满火力仍掉 P、位置在复活前采样、30/60/120/144/240 显示 FPS、暂停与重开，并复验本体接触合并。

```bash
cmake --build build-debug --target koumakyou koumakyou_tests koumakyou_lifecycle_tests -j 6
./build-debug/koumakyou_tests --gameplay-only
./build-debug/koumakyou_lifecycle_tests /tmp/player-miss --player-miss-only
ctest --test-dir build-debug --output-on-failure
```
