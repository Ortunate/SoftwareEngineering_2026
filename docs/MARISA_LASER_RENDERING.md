# 魔理沙激光渲染

魔理沙自机激光由透明队列按主弹、演员等对象的深度切分。旧路径为每个区间重画完整的主体与外辉光，最后才在片元着色器中 `discard` 区间外像素。满 Power 的近景外辉光覆盖范围较大，切点增加时会重复着色大面积屏幕。

现在通过顶点着色器输出两个 `gl_ClipDistance`，在栅格化之前裁掉当前区间以外的三角形。裁剪仍使用整束本地轴向坐标，保留原模型的法线、端帽、颜色、辉光、透明度和排序；切口不新增封盖。两个裁剪槽只在魔理沙激光立即绘制期间启用，返回前关闭，避免影响其他 shader。独立审阅器继续使用片元裁剪。游戏的 `clipGeometry=1` 分支关闭片元丢弃，避免 MSAA 逐采样点裁剪后又按片元中心丢弃，造成切口缺样。

本次不改变激光碰撞、穿透伤害、发射节奏或寿命，也不降低分辨率、MSAA 或弹量。

## 第一人称尺寸与起点

局内主体显示半径改为 `判定半径 × 当前副机缩放 × BeamVisualScale() × 0.35`，最宽档外壳半径仍按三倍主体计算。显示尺寸与判定半径分离，主体全宽可收在已缩小为六成的星形副机内。

显示圆柱段起点沿射线前移 `外壳半径 + 0.1` 世界单位，让整个后端帽位于副机前方，避免其向后包住第一人称镜头。显示圆柱的远端中心保持原射程，长度随起点前移相应缩短。`SampleMarisaBeamGeometry` 统一提供绘制和透明队列使用的起点、终点及半径，避免排序仍按判定起点切分而错位。透明队列用包含端帽与外辉光的胶囊投影包围盒筛选交集，避免无关精灵增加切分，也不会误用原 ANM 光带的宽度排除立体光壳。

持续激光每次更新时同步当前 `OptionScale()`，因此从远处瞄向近目标时，已有激光也会与副机一起缩小。显示几何不依赖观察相机，旁观/录像视角看到相同的世界光束；碰撞与伤害仍使用原始发射点、判定半径和射程。

回归检查包含四档 Power、低速/高速、三组转向/俯仰，以及目标从 20 世界单位突然移到 0.05、1 世界单位的过程，检查整个外壳距镜头前方至少 0.05 世界单位、远端中心和持续伤害配置保持不变。

最终构建、7/7 CTest、模型像素/多重采样、透明遮挡与魔理沙射击集成检查通过。隔离主弹后，满火力高速/低速激光分别影响约 19.2% / 12.7% 的整幅画面像素，旧版本为整屏染色。截图与日志保存在本机忽略目录 `output/render-performance/marisa-first-person-20261103/`。

当前几何另做一轮串行短测：预热 2 秒、采样 8 秒，Debug、4×MSAA 的 `marisa-lasers` 窗口 P95 为 11.759 ms，GPU 区间 P95 为 7.527 ms。端帽与辉光的保守投影筛选得到 74 个片段、1060 次绘制。此轮用于确认当前场景可正常运行，不与下文旧几何的三轮结果计算收益比例。

## 复现

`marisa-lasers` 场景直接通过生产 `Player` 发射满 Power 的魔理沙激光及主弹，推进 20 个 60 Hz 内容帧后冻结；另外包含 2048 颗敌弹和 24 个演员。它覆盖正式自机激光的近景尺寸，不能用已有 `lasers` 敌激光场景代替。

```bash
cmake --build build-debug --target koumakyou render_benchmark -j 6
./build-debug/render_benchmark assets/runtime /tmp/marisa-lasers \
  marisa-lasers 3 12 3 4 0
```

固定快照只测生产绘制链，不代表完整动态遭遇；性能数据应单独顺序采样，不与构建或其他图形测试并行。

## 裁剪优化的本机结果

以下记录对应仅提前裁剪、尚未进行上述第一人称尺寸/起点及后续抛光材质调整的版本，不作为当前视觉参数的重新采样结果。

2026-11-03，Apple M5，原生 arm64 Debug；逻辑窗口 1100×760，实际 framebuffer 2200×1520，4×MSAA，关闭 VSync，不限 FPS。每轮预热 3 秒、采样 12 秒，以 AB/BA/AB 顺序各运行三轮，不与构建或其他图形测试并行。基线为 `557c9ba` 的生产渲染代码及原 shader，两版使用同一份新增场景的压测工具。

以下为三轮各自 P95 的中位数，单位 ms。CPU 绘制墙钟可能包含驱动等待，GPU 区间覆盖绘制准备及提交，两者不能相加。

| 指标 | 基线 | 优化后 | 变化 |
|---|---:|---:|---:|
| 窗口 P95 | 25.337 | 13.466 | -46.9% |
| CPU 绘制 P95 | 23.026 | 10.058 | -56.3% |
| GPU 区间 P95 | 23.235 | 9.266 | -60.1% |
| 每帧绘制调用 | 716 | 716 | 不变 |
| 激光排序片段 | 38 | 38 | 不变 |

三轮窗口 P95 的范围为基线 24.047～27.466 ms、优化后 10.822～13.536 ms；桌面呈现存在波动，本表只说明该固定场景的局部收益。没有将其视为完整游戏 FPS 或全场景性能结论。

三组窗口截图均有 837 个像素发生变化，占实际 framebuffer 约 0.025%，最大通道差为 16；硬件裁剪按 MSAA 采样点覆盖切口，因此不宣称窗口截图逐像素相等。另用无 MSAA 的参考像素比较和 MSAA 整束/分段连续性用例检查几何、高光与接缝。

本机原始数据、环境与二进制签名、截图及验证日志保存在忽略目录 `output/render-performance/marisa-lasers-20261103/`。其中 `results.csv` 为六轮结果，`summary.json` 为中位数，`binaries/` 保留两版程序和 shader；大体积模型、图集通过符号链接借用工作区，并记录素材签名，后续修改素材时不能直接混用旧结果。

## 验证

- `projectile_runtime_tests` 将正式裁剪路径与关闭硬件裁剪、仅使用原片元丢弃的参考路径比较，覆盖两种半径、四个视角、正交/透视、首尾端帽和薄片区间；包含相机位于外辉光内部的情况。仅允许栅格化舍入误差，空画面不能作为通过依据；同时检查两个裁剪槽在返回后关闭。另在真实 4×MSAA 窗口比较整束与 20 段的画面，只容许孤立裁剪交点的采样舍入差，防止连续接缝；恢复旧的重复裁剪后此用例必须失败。
- `koumakyou_sprite_overlap_tests` 检查统一透明队列的前后遮挡及混合状态。
- `koumakyou_lifecycle_tests --marisa-only` 检查两种魔理沙射击模式、低速/高速、激光显示与淡出，以及 30/60/144 FPS 下的持续穿透伤害和分数；隔离主弹后的满火力激光还须留下至少半屏的未受影响像素，防止整屏光壳通过可见性检查。
- `projectile_direction_tests` 检查模型方向约定。
