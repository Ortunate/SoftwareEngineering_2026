# koumakyou 项目 NABCD 需求分析

更新日期：2026 年 11 月 4 日。

本文用于软件工程课程报告与项目展示，以《东方红魔乡：新典》全流程关卡的第一人称 3D 化改造为产品主线，结合当前仓库的代码、内容目录与专项文档重新分析 Need（需求）、Approach（做法）、Benefit（好处）、Competitors（竞争）和 Delivery（推广）。

分析范围为更新时的工作区，包括正在集成的弹体材质、渲染与提示音改动，不等同于某个已发布版本。文中区分已接通功能、已有验证记录和仍需验证的体验收益；用户动机与市场判断不作为已完成访谈或运营统计的结论。

## 一、项目定位与最新现状

`koumakyou` 是使用 C++20、raylib 和 CMake 开发的本地单人三维弹幕射击游戏，面向 Windows 和 macOS。玩家以第一人称观察，在具有高度与纵深的战场中移动、射击、使用 Bomb 并躲避弹幕，沿原作关卡推进红雾异变的旅程。

**产品定位：让东方爱好者与空间射击玩家以第一人称、三维移动和实体弹幕，重新体验《东方红魔乡：新典》的完整关卡与符卡挑战。**

项目已从第一面验证原型推进到主线、Extra、练习及结果保存相互衔接的可玩系统。当前范围如下。

| 维度 | 当前项目现状 | 应明确的边界 |
| --- | --- | --- |
| 主线流程 | 一至五面开放 Easy／Normal／Hard／Lunatic，六面开放 Normal／Hard／Lunatic；支持连续闯关与逐关练习 | Easy 在五面结束，不存在可玩的 Easy 六面分支 |
| 独立 Extra | 已注册独立 Extra Start、道中与关底流程，并接入条件追加战 | 不作为主线第五难度，不在主线六面后自动进入；内部使用 Normal 脚本上下文不代表主线 Normal |
| 角色与机体 | 灵梦、魔理沙均可开局，提供灵／梦／魔／恋四组合及各自攻击 | 四组合的符卡遇见、取得与练习成绩分别记录 |
| 符卡练习 | 按七位 Boss 组织 50 组、131 个难度变体：主线 118 个、Extra 13 个均已接通 | 当前组合须在实际关卡遇见对应变体才可练习；132～134 仅用于追加战及战斗记录，不新增练习入口 |
| 结局与成绩 | 主线接入六种结局脚本、观看记录、命名及成绩选存；排行榜按五种难度类别、四机体与标准/挑战分别保存前十 | Extra 不进入这六种主线结局；制作人员演出未接入；分关成绩与全程排行榜口径不同 |
| Replay | 已有保存、60 个固定槽位、命名、列表、播放、定位、倍速及第一/第三/自由观察视角 | 播放不写入成绩或解锁；协议不兼容时拒绝播放；短轨迹测试不能替代全部长录像终局验收 |
| 三维弹体 | 正式游戏已接入十类敌弹、两套参数激光、自机弹、副机及部分 Bomb 模型；模型姿态、缩放与危险体积相互对应 | 已有模型独立审阅与运行时测试，游戏内组合效果及新危险体积仍需人工验收；兼容外观保留旧路径 |
| 运行与验证 | 具有独立参考、60 Hz 源差分、默认 120 Hz 演员更新、图形生命周期和渲染专项记录 | 内容帧仍为 60 Hz；现有弹池容量为 16384，容量不等于所有设备的流畅性承诺 |

历史 README 和部分专项文档保留较早阶段的描述。涉及开放范围，以当前关卡注册、符卡目录及较新的专项记录交叉核对；例如“仅 Normal”“仅两张练习符卡”和“8192 弹池”已不能概括当前实现。

## 二、N：Need——为什么要做这个软件

### 2.1 最重要的需求

**核心需求是：让希望以新方式重温《东方红魔乡：新典》的玩家，能够亲自置身弹幕空间，完整经历红雾异变，并通过观察、练习和策略逐步掌握挑战。**

对于熟悉原作的玩家，故事、角色、音乐、关卡与符卡构成了有辨识度的游戏记忆。第一人称改造使他们能够重新探索：当弹幕具有真实高度、纵深和体积时，熟悉的攻击会形成怎样的空间路线？升降、转向、接近与后退如何影响躲避和攻击？

完整流程使这一动机能够延续。玩家在早期关卡学习空间判断，随后应对不同 Boss 和符卡，再通过结局与成绩确认整轮成果。当前的多关、多难度和 Extra 已为这一体验提供内容基础；练习与 Replay 则帮助玩家把一次游玩转化为持续理解与改进。

项目的原始目的仍是提供有价值的经典重温与空间挑战。模型数量、弹池规模和测试数量都不能直接证明玩家觉得好玩。

### 2.2 目标用户与场景

| 用户群体 | 典型使用场景 | 主要诉求 |
| --- | --- | --- |
| 愿意尝试改编的东方玩家 | 使用熟悉的角色走完主线，比较经典符卡的三维变化 | 保留内容辨识度，获得值得重新通关的新体验 |
| 弹幕挑战与策略研究玩家 | 练习不同难度符卡、挑战 Extra、研究录像中的路线 | 攻击规则清楚，失败可解释，练习成果可积累 |
| 对东方题材感兴趣的键鼠射击玩家 | 使用鼠标观察和三轴移动逐步学习弹幕玩法 | 操作可控、目标明确、空间信息容易理解 |
| 喜欢游戏改编及开发的课程受众 | 观看实机与 Replay，对照需求、实现和测试证据 | 看清三维改造带来的交互变化与工程取舍 |

教学展示是附加价值。玩家是否愿意持续推进、练习与重玩，仍是需求是否成立的关键。

### 2.3 当前需要验证的痛点

第一人称减少了同时可见的威胁范围，实体弹幕使距离与危险体积的判断更加重要；更多关卡也增加了长期操作负担。因此，当前需求验证应从“能否做出三维弹幕”推进到以下问题：

1. 玩家能否判断危险方向、距离与受击原因，而非只觉得画面新鲜？
2. 高度与纵深是否提供有效策略，是否存在长期停留即可绕过主要攻击的位置？
3. 机体、难度、练习入口和遇见解锁是否容易理解，能否帮助玩家突破难点？
4. 主线及 Extra 的连续体验是否具有节奏、成长感与再次挑战的吸引力？
5. 实体弹幕、材质与演出是否增强辨识度，还是增加遮挡、疲劳或性能负担？

目前没有可用于证明市场规模、留存率或用户满意度的调研数据，应通过分组试玩与连续游玩观察回答这些问题。

## 三、A：Approach——如何满足需求

### 3.1 用已贯通的关卡承载完整旅程

当前主线已支持适用的四种难度及连续切关，Extra 使用独立入口与结果流程。各关拥有显式时间轴、命名演员行为、Boss 配置、对白、音乐与场景；主线结局、成绩选存及 Replay 将战斗后的成果保存连接起来。

做法的重点是保留各关的攻击特征和推进节奏，并将跨关资源、结束条件和结果归属统一处理。Easy 五面终止、其他主线六面终止以及 Extra 独立收尾，都是实际流程差异，需要在游戏与介绍中清楚表达。

### 3.2 用空间交互与实体弹体创造新体验

玩家通过鼠标观察、三轴移动、射击、低速和 Bomb，在同一三维空间中判断攻击与防御。摄像机位置与玩家判定中心一致，场景、边界和 HUD 提供位置与战斗参照。

三维改造已经从运动轨迹扩展到弹体本身：正式渲染接入敌弹、激光、自机攻击、副机与部分 Bomb 模型，模型显示与碰撞共享姿态和正常缩放；危险体积通过 CPU 几何查询，特殊孔洞与装饰光效按实际约定区分，未绑定模型的外观保留兼容判定。

这些手段使高度、纵深、弹体方向和体积都能影响玩家判断。后续应重点验证模型与判定是否容易对应，以及复杂场景下能否看清路线；不能把模型独立验收等同于正式战斗体验已经充分验证。

### 3.3 用练习、记录与 Replay 建立学习循环

| 当前做法 | 解决的问题 | 对用户的作用 |
| --- | --- | --- |
| 标准与无限残机挑战模式 | 玩家对失败成本的接受程度不同 | 可分别追求严格挑战或持续体验，成绩分开保存 |
| 一至六面逐关练习，按难度过滤有效入口 | 完整流程重试时前置耗时较长 | 针对薄弱关卡集中训练 |
| 七位 Boss、50 组、131 变体的符卡练习 | 难点分散在不同关卡和难度 | 以实际使用者查找目标，按四机体独立积累遇见与练习记录 |
| Replay 定位、倍速与多观察视角 | 受击瞬间及空间关系难以复盘 | 重新观察真实轨迹，从其他角度研究安全路线 |
| 命名成绩与分类前十记录 | 完成一轮后需要保留成果与比较目标 | 区分难度、机体和模式，形成后续挑战目标 |
| 键位、灵敏度、音量和显示设置 | 操作习惯和设备差异影响学习 | 减少重复配置并调整个人体验 |

学习循环为：**进入关卡 → 遇见攻击 → 定向练习 → 保存或查看 Replay → 调整策略 → 再次挑战完整流程。** Replay 已是现有产品能力，后续应研究如何让玩家发现并有效使用它。

### 3.4 用内容分层与验证控制改造质量

关卡时间轴负责何时发生事件，普通演员配方与协程负责移动和发弹，角色 Boss 行为负责攻击，阶段配置负责技能组合、跳转和血条；素材与对话独立管理。共用框架使新增难度和复杂演出可以沿同一规范扩展，并便于定位差异。

源内容帧按 60 Hz 解释，生产演员默认按 120 Hz 更新，显示帧率与逻辑时序分离。独立参考差分、真实 Game 路径、暂停与资源释放测试共同检查改造边界。异步加载与分帧上传用于保持加载页反馈，实例批次与透明排序用于处理大量模型。

现有验证证明的是各专项记录列明的范围。原生统计门控、部分效果、动态 rank、全局随机交错、满池哨兵和完整等价审计仍有延期项，不将当前项目称为 1:1 原生复刻。渲染优化也存在不同负载收益不一致的情况，不宣称所有场景全面提速。

### 3.5 当前迭代重点

目前重点从补齐基础关卡转向完整体验与交付质量：

- 验证实体危险体积、材质高光、密集弹幕与演出交错时的可读性和公平性。
- 对不同机体、难度及长流程继续做回归，重点核对切关、结局、成绩和 Replay 的衔接。
- 通过试玩完善操作说明、空间提示和练习/录像功能的发现路径。
- 分开记录进行中的材质、音效和渲染优化与已验收版本，持续维护延期审计边界。
- 整理双平台发布包、支持说明与素材分发条件，形成面向体验者的交付入口。

## 四、B：Benefit——用户能够得到什么好处

### 4.1 以新的方式完整重温经典

连续主线、独立 Extra、双角色对白、音乐与结局，使玩家能够把空间战斗串成一段完整旅程。与早期单关演示相比，当前系统已经提供逐关适应、面对不同攻击主题并完成整轮的内容基础。

预期收益是让原作玩家在保留熟悉感的同时重新探索路线，让射击玩家以第一人称交互接触东方弹幕。临场感和成长感是否足够强，仍需通过玩家体验验证。

### 4.2 将失败转化为可观察、可练习的改进

符卡练习减少重复前置流程的时间，Replay 允许回看速度、方向和空间关系，独立记录展示每个组合的尝试与取得。玩家可以围绕具体失误建立训练目标，而不必每次从头猜测问题。

Replay 的第三人称和自由视角还便于展示被第一人称遮住的空间结构，为攻略交流与课程演示提供现成工具；这些视角用于观察录像，不改变正式游玩的判定或输入。

### 4.3 提供不同投入程度的挑战目标

玩家可以选择持续体验剧情与场景，也可以深入研究更高难度、Extra 或某张符卡。不同角色机体、成绩类别与练习记录支持反复挑战；无限残机模式降低中断成本，但不等于无敌，也不能与标准成绩混同。

### 4.4 收益与证据的区分

| 预期收益 | 当前已有基础 | 仍需收集的用户证据 |
| --- | --- | --- |
| 完整重温与通关成就 | 主线、Extra、结局和成绩流程 | 继续下一关的意愿、退出原因与完成体验 |
| 有意义的空间策略 | 三轴移动、各关弹幕、模型方向与危险体积 | 玩家主动利用高度/纵深的实例，受击原因能否解释 |
| 更高效地攻克难点 | 逐关练习、131 变体与四机体独立记录 | 是否容易找到目标，练习后是否能形成有效策略 |
| 能够复盘和分享 | Replay 保存、定位、倍速与观察视角 | 玩家是否会使用录像定位问题、制作攻略或展示 |
| 长流程操作稳定舒适 | 可配置输入、暂停、资源与渲染专项测试 | 连续游玩中的疲劳、不适、卡顿与可读性反馈 |

建议邀请东方玩家和键鼠射击玩家分别进行短时上手、目标练习及连续闯关，记录需要帮助的环节、自愿重试行为和具体意见。工程测试与玩家收益相互补充，不能用构建通过或弹体数量代替满意度结论。

## 五、C：Competitors——竞争与差异化

竞品资料于 2026 年 11 月 4 日通过官方商店或发行商页面核对；下表的竞争判断为项目分析，不是竞品官方结论，也不涉及销量或市场份额推断。

| 产品与关系 | 官方公开特点 | 与当前项目的比较及启示 |
| --- | --- | --- |
| [《东方红魔乡：新典》](https://store.steampowered.com/app/4659620/)：改造来源与直接替代选择 | 二维纵向卷轴弹幕、灵梦/魔理沙、不同射击方式、无限残机模式及更新后的画面与音乐 | 本项目要以第一人称空间策略、实体弹幕和全流程改造形成重玩理由；角色与无限残机本身不是独有优势 |
| [HYPER DEMON](https://store.steampowered.com/app/1743850/HYPER_DEMON/)：第一人称高强度挑战的相邻竞品 | 快速击杀驱动难度与分数，球面宽视野、后方威胁显示、全球排行榜和回放分享 | 本项目已有本地 Replay 和分类成绩，但不能宣称具备在线排名或同等分享生态；需要继续验证空间威胁感知 |
| [Touhou: New World](https://www.xseedgames.com/games/touhou-new-world/)：东方题材动作体验的间接竞品 | 东方题材动作 RPG，以动作战斗应对弹幕 | 本项目的选择理由是原作流程与符卡的第一人称改造，以及定向练习和录像研究，而非单纯使用东方题材 |

### 5.1 当前能够展示的差异

**原作主线与 Extra 的内容组织、第一人称三维移动与实体弹幕、符卡练习及多视角 Replay 的组合**，已具有可演示的实现基础。玩家既可以完成连续挑战，也可以围绕一张符卡观察、研究和重试。

这种组合不构成“市场首创”或“整体优于成熟作品”的证据。它的实际吸引力应由试玩者给出的选择理由与重复游玩行为检验。

### 5.2 竞争中的主要不足

当前竞争压力集中在空间信息、整体打磨与交付：俯视弹幕便于观察全局，第一人称需要额外建立公平的威胁感知；实体模型可能增强辨识，也可能遮挡路线；成熟产品在性能适配、引导、发行与社区生态上有更完整的积累。

项目应优先把已接通的完整内容打磨为易启动、看得清、学得会、愿意重玩的体验，清楚说明适配和审计边界。当前没有用户研究、商业发行或社群规模数据，不能推导已有市场优势。

## 六、D：Delivery——如何推广与交付

### 6.1 当前可用的传播信息

> 以第一人称重新走进红雾异变，在三维弹幕中挑战主线与 Extra，通过符卡练习和多视角 Replay 研究自己的路线。

说明页应同时标注 Easy 五面终止、其他主线六面终止、Extra 独立流程，以及当前版本仍需验收的模型组合与适配边界，避免把功能覆盖等同于原生完全等价。

### 6.2 从单关展示转向完整体验展示

| 渠道与阶段 | 当前可使用的内容 | 期望行为 |
| --- | --- | --- |
| 课程汇报与校内试玩 | 真实主线/Extra 画面、机体与难度选择、符卡练习、结局和记录流程 | 理解需求、实际体验并反馈关键问题 |
| 东方、弹幕及独立游戏兴趣社区 | 不同关卡的空间路线短片、实体弹体对照、多视角 Replay、符卡攻略 | 看懂改造价值，进入项目说明和试玩入口 |
| 项目主页、仓库与版本说明 | 功能矩阵、支持平台、运行方式、操作、已知问题和测试边界 | 获取匹配版本并成功启动 |
| 后续迭代与玩家交流 | 体验问题的前后对照、录像分析、不同机体和难度挑战 | 再次试玩、提交可复现反馈并推荐 |

仓库已有课程汇报脚本、素材清单、实机/录像导出和独立模型审阅工具，可用于制作展示材料；工具存在不代表 PPT、公开发布页、社区合作或商业发行已经完成。

### 6.3 交付路径与准备工作

目标路径为：**看到实机 → 了解范围与要求 → 获取版本 → 调整操作 → 推进主线或 Extra → 练习/回看 → 通关、重试或分享。**

工程上已有 Windows/macOS 共用构建、Windows 项目内工具入口和 macOS 原生 app 打包方式。面向普通玩家的发布仍需逐平台整理并验证最终包，写清依赖、输入、存档位置、录像兼容性与已知问题，不能用开发机可运行代替发行包验收。

已使用原作素材与自制/重绘资源，应依据项目资源说明整理来源和分发条件；解码器或引擎的开源许可不自动覆盖原游戏素材。收费、渠道与公开范围在分发条件明确后决定。当前任务仅更新分析，不执行发布或联系社区。

### 6.4 推广效果评价

重点评价“兴趣—成功启动—有效体验—继续推进—练习/回看—重玩或推荐”，而非只统计播放量。记录体验者在哪一步退出，区分操作理解、难度、性能、内容偏好和运行故障；对使用 Replay 的玩家，进一步了解它是否帮助解释受击和改进路线。

上述为后续观察方案。目前没有可报告的真实下载、转化、留存、收入或满意度数据；先用现场观察和自愿反馈建立基线，再决定扩大推广。

## 七、NABCD 总结与下一步判断

| 模型 | 当前论述重点 | 下一步判断依据 |

| N：需求 | 以新的空间视角完整重温经典，并逐步掌握挑战 | 玩家是否愿意继续下一关、练习与重玩 |

| B：好处 | 完整旅程、空间探索、定向练习和可观察的复盘 | 用户能否形成策略、解释失败并感受到进步 |

项目后续重点是把已具备内容覆盖的可玩系统打磨为完整、清楚且可交付的体验。原生完全等价、玩家收益和公开发行分别需要自己的证据，不相互替代。
