# 激光渲染与性能回归

普通激光原先在每个透明精灵的深度处切分，包括屏幕上完全不重叠的对象。2048 颗独立深度的弹幕与 8 束激光会产生 16,392 个激光片段。加色片段每次绘制后还会恢复 Alpha，反复触发 raylib 的批次提交；本机调用栈采样显示主要耗时在混合切换引起的 `rlDrawRenderBatch`、顶点缓冲上传与 GPU 同步等待。

当前实现用 `AnimatedBillboardVertices` 和 `AnimatedBeamVertices` 的实际绘制四角计算投影范围。先排除整束投影不重叠的对象，再检查精灵四角实际深度区间内的光带；不能仅比较长激光的整体包围框，也不能仅检查倾斜精灵的中心深度。只有可能发生遮挡的深度才产生切分。

相邻同混合模式的原生激光片段连续提交。`DrawAnimatedBeam` 保留当前 ANM 混合模式，调用方在绘制其他几何前设置对应模式，并在透明通道结束时恢复 Alpha、深度写入及背面剔除。

必须保持以下约定：

- 切分参数 `from/to` 仍相对整条光束，UV 沿整束连续；自机激光的脚本宽度、镜像、透明度和加色语义不变。
- 投影使用相机平面坐标，透视为 X/Z、Y/Z，正交为 X、Y；两种对象使用同一坐标约定，比较不依赖窗口尺寸。
- 原生公告板的包围范围包含 ANM 位移、旋转、镜像与缩放；深度区间包含全部四角，光带裁分同时计入侧向宽度的深度偏差。
- 跨越相机平面或无法安全界定的投影保守保留切分；旧 PNG/几何激光沿用原切分规则。
- Bomb 巨束继续按演员及既有轴向区间分段。激光碰撞、预警、伤害和模拟时间不依赖这些渲染片段。

`SpriteRenderer::LastBeamSegmentCount()` 返回上次绘制的普通激光片段数，包含预警、不包含 Bomb。性能回归应同时观察片段数和耗时，避免用减少弹量或改变画面掩盖问题。

## 验证命令

```bash
cmake --build build-debug --target koumakyou koumakyou_tests koumakyou_ui_tests sprite_benchmark koumakyou_sprite_overlap_tests -j 6
ctest --test-dir build-debug --output-on-failure
./build-debug/koumakyou_sprite_overlap_tests /tmp/laser-overlap assets/runtime
./build-debug/sprite_benchmark assets/runtime
./build-debug/sprite_benchmark assets/runtime --stress
```

像素回归覆盖透明遮挡、UV 连续、双加色激光累加、与普通几何预警混合、渲染状态恢复，以及透视/正交相机下的无关密集弹幕、倾斜公告板、ANM 位移/镜像、自机宽度变化和相机平面退化。1024 颗远离光束的原生弹幕不应增加激光片段数。

基准使用 1100×760 隐藏窗口、关闭帧率限制。混合场景为 2048 颗确定性分布、各自深度不同的原生弹幕，叠加 0/8 束敌方与自机素材激光；`--stress` 追加 64 束。每档暖机 2 帧、测量 5 帧，计时包含渲染与提交/呈现，不包含资源加载或游戏模拟。跨版本比较须使用相同构建类型、负载和图形环境。

2026-10-27，本机 macOS、Debug 构建的同负载观测如下。基线使用 `2a31916` 的渲染实现与新增混合场景；优化版列出最近一次复测结果。

| 场景 | 基线激光片段 | 优化后激光片段 | 基线毫秒/帧 | 优化后毫秒/帧 |
|---|---:|---:|---:|---:|
| 2048 弹 + 8 束激光 | 16,392 | 57 | 11,020.9 | 22.7 |

优化版的 2048 弹 + 64 束激光压力场景为 452 个片段、84.0 毫秒/帧。无激光的 2048 弹场景同次复测为 4.1 毫秒/帧。固定压力场景用于定位渲染开销，不能直接换算包含模拟及其他绘制的整关卡帧率。
