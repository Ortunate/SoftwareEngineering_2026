# Stage 从原典数据到项目代码的方法与原则

本文是本项目所有关卡移植的通用方法，适用于后续 Stage 的首次接入、已有关卡重构和输入版本更新。每关都应按本文完成数据溯源、语义分析、组件提炼、时间轴编排及验收。Stage 1 仅作为已完成案例，其中的数量、预设、子程序编号和遭遇时刻不构成其他关卡的固定模板。

每次移植先指定输入游戏及版本、目标关卡、难度、角色/御札和入口，再依据数据恢复其出生时序、路线、攻击结构、阶段与演出，接入项目三维玩法。当前已验证的源版本为本机《东方红魔乡：新典》；文件格式、指令语义和数值不能未经核对就套用于其他版本。生产代码统一使用世界坐标和默认 120 Hz 行为更新，项目内容帧号保持 60 Hz；原典对照按源时钟独立验证。已提取数据、已实现内容和原生引擎完整还原是不同的验收范围。

## 1. 先确定输入和验收范围

先记录游戏版本、输入文件 SHA-256、来源包及提取文件名，再开始解释内容。同名文件也可能来自不同版本，不能混用一份 ECL 的时序、另一版本的动画编号和第三份数值表。每关单独记录其输入、目标分支、对应源码和验证结果；可参考 [Stage 1 数据对照](STAGE1_REFERENCE.md) 与 [统一战斗数值目录](NATIVE_COMBAT_DATA.md) 的溯源格式。

| 数据 | 本项目从中读取什么 | 对应产物或入口 |
|---|---|---|
| 目标关卡 ECL，当前新典通常为 `ecldataN.ecl`，实际包名与文件名需核对 | 出生时间、坐标、子程序、HP、分数、掉落、难度分支、移动、攻击、阶段回调 | 本关 `timeline.cpp`、`behaviors.*`、参考指令与出生差分 |
| 目标关卡 MSG、对应本地化数据 | 分角色台词、等待、输入锁、表情、立绘与音乐切换 | 本关 `dialogue.cpp`、`DialogueLine`、`DialogueCue` |
| DDS / ANM | 图像、脚本编号、动画重启、显现、颜色、击破与局部变换 | 素材目录、`manifest.cpp`、`ids.hpp`、动画播放器 |
| `th06nc.exe` | 四机体原始火力表；部分位于执行代码中的结算规则另行核对 | `native_combat`、伤害规则；不是 ECL 时间轴来源 |
| 原游戏实机与录像 | 核对实际表现，帮助定位语义、演出或三维适配问题 | 本地审阅记录与图形回归，不用于替代可提取的数值 |

为目标关卡列出入口、难度、出生请求、可达子程序、Boss 遭遇/阶段、对话分支和结束条件，再定义覆盖范围。数量必须从本关输入和可达控制流推导，不能沿用别关的预期值。数据目录中存在记录或素材，不代表时间轴和行为已经实现；`DataOnly` 不能直接当作可玩状态。

案例：Stage 1 当前覆盖 Normal 的 222 次道中出生请求、五种小怪配方、道中露米娅、关底四阶段及对话/结算；参考文件含 38 个子程序、筛选后的 570 条指令，行为差分覆盖 28 个可达子程序。这些数值只用于一面的回归，未接入的其他难度或原生练习入口继续单独标明。

## 2. 只读提取，保留可追溯的中间结果

使用适配目标版本的工具只读提取本地资源，ECL 与 MSG 按对应格式反编译。当前新典工具链的已完成案例见 [数据来源与复现](STAGE1_REFERENCE.md)；新关卡仍需确认输入结构和工具支持范围，不能只修改文件名就认为解析正确。

处理时保留文件哈希、文件偏移、子程序编号、局部指令序号、难度掩码及必要的参数掩码；EXE 表保留 RVA。它们用于从一条项目配置追溯到输入，不作为生产行为的分支编号。

原始包、EXE、临时反编译工具、解包目录、完整反汇编和截图报告保留在本地审阅目录。进入仓库的是项目需要的素材、经过审阅的数值源码、独立测试基准和方法说明；运行游戏不依赖原作安装、解包目录或 Python。

参考指令优先生成到临时目录核对差异，再更新该关的测试夹具。现有 Stage 1 工具的操作示例如下：

```bash
thecl -d 6 /tmp/ecldata1.ecl /tmp/stage1.ecl.txt
python3 tools/import_stage1_reference.py /tmp/stage1.ecl.txt --output /tmp/stage1-reference
```

`import_stage1_reference.py` 是一面专用适配器，支持按 E/N/H/L 筛选反编译文本及 `--binary-all` 导入真实 ECL；保留恰好 38 个连续编号子程序的校验，并逐指令核对旧 Normal 基准。`stage_reference.py` 复用二进制结构和参数解析，按关卡显式校验子程序数量与 SHA-256，生成二至六面各自的四难度测试夹具。六面新典 `201` 保留原始操作码和参数，不在导入阶段改写为普通发射。参考数据存在不等于解释器支持完整执行语义；后续关卡仍须增加本关指令、原生扩展及可达分支的独立验证，不能删除一面校验或把一面解释器当作新关卡的完整基准。测试执行能力不得进入生产引擎。

`tools/inspect_stage_scripts.py` 可在首次移植前直接只读审阅本版本 ECL 的结构、出生记录及保守调用闭包；未知指令保留原字节，不执行或猜测语义。二至六面的输入身份、静态计数与尚未完成项见 [逐关审阅记录](STAGES_2_6_REFERENCE.md)。该工具不生成生产事件表，也不能用静态闭包代替实际行为覆盖。

统一战斗数值导出器要求目录中包含 `ecldata1.ecl`～`ecldata7.ecl`，不能只提供第一面。先导出 JSON/CSV 审阅，再显式导入源码：

```bash
python3 tools/export_native_combat_data.py /本机安装目录/th06nc.exe /tmp/ecl目录 --output output/native-combat-data
python3 tools/export_native_combat_data.py /本机安装目录/th06nc.exe /tmp/ecl目录 --output output/native-combat-data --runtime-output src/gameplay/data/native_combat_data.inc
```

导出成功只代表结构解析通过。修改数据版本后仍需核对调用关系、实际可达分支和表现，不能将导出器当作关卡代码生成器。

当前统一导出器将七关标记为 `Playable`；Extra使用独立目录入口和成绩身份，不能作为主线第五套难度。新Stage真正完成接入时，应同步可玩状态的生成规则和内容注册，避免只手改生成目录，下一次导出又覆盖集成状态。可玩状态不代表未核对的原生动态rank或练习指令路径已还原。

## 3. 先还原执行语义，再提炼行为

反编译文本中的一条指令不等于一个敌人，一段子程序也不一定等于一个完整预设。需要从出生入口、调用、跳转和生命/超时回调出发，追踪实际执行路径。

分析每个可达子程序时，分别记录以下内容：

| 维度 | 必须核对的问题 |
|---|---|
| 时钟与控制流 | 时间是开局、出生、子行为还是阶段时间？调用是否冻结父时钟？跳时、循环及返回发生在何时？ |
| 移动 | 初速、方向、关键帧、角速度、加速度、插值、边界、镜像、退场条件是什么？ |
| 技能 | 发射时刻、扇形/环形、瞄准方式、弹种/颜色、角距、速度层、rank 修正与延迟运动是什么？ |
| 状态与副作用 | HP、受伤开关、动画重启、音效、清弹、掉落、生命阈值、回调及跨阶段保留值是什么？ |
| 实例参数 | 出生点、生命、分数、掉落、镜像和随机位置是否来自时间轴？哪些值真正属于共享行为？ |

当前 TH06 反编译格式的 `!E/N/H/L` 难度选择会持续影响后续指令，不能只删除带前缀的一行。按目标难度过滤后，跳转目标必须重新对应子程序内指令索引；不能把文本行号当执行索引。静态出生记录、子程序调用次数、实际生成数量也要分别统计；其他版本先确认其掩码和跳转语义。

对扫描弹流，先算出真实发射时点，再表达为参数循环。例如 Stage 1 的非符扫描进入后第 2 内容帧首发，之后每 2 帧发射；其他攻击需推导自身首发帧和周期，不能照抄该序列。显现结束后才开始延迟转向等时序也须明确建模。

未知参数应查证、保留未实现状态或通过严格接口拒绝，不能填零、猜测默认 HP，或从录像中估算一个看起来相近的数值。`native_combat::RequireLiteral` 对缺失、动态寄存器等无法直接求值的记录拒绝返回假常量。

## 4. 将数据归入项目中的正确层

下表中的 `stageN` 表示待接入关卡目录，是组织约定，不代表该关已经实现。

| 内容 | 通用代码归属 | 编排原则 |
|---|---|---|
| 全关出生与遭遇时机 | `src/stages/stageN/timeline.cpp` | 显式静态 `StageEvent` 表，保存逐实例参数与事件依赖 |
| 通用运动 | `src/gameplay/actors/movement.*` | 世界坐标的极坐标运动、插值、边界；不认识 ECL 或具体关卡 |
| 通用攻击 | `src/gameplay/actors/skill.*` | 带参扇形/环形、速度层、瞄准、光束与运动特效 |
| 演员执行与所有权 | `src/gameplay/actors/behavior.*` | 独立实例状态、协程、固定更新步、生命周期和演员池 |
| 关卡配方与复杂攻击 | `src/stages/stageN/behaviors.*` | 普通演员命名配方与参数化协程；Boss 专属行为归角色模块 |
| Boss 角色和公共执行器 | `src/gameplay/bosses/<角色名>.*`、`configured_boss.*` | 八个角色内嵌 Behaviors 实现专属移动、攻击和演出，ResolveSkill 绑定血量/时限，实例独占状态 |
| 每场 Boss 启动配方 | `src/stages/stageN/boss_config.*` | `StartConfig` 声明每阶段技能组合、跳转、血条比例/颜色/排列、对白入口、退场与奖励，不保存技能 HP；Boss 解析并绘制血条，`StartBoss` 事件借用命名 `Battle` |
| 数值、素材与对话 | `native_combat`、`manifest.cpp`、`ids.hpp`、`dialogue.cpp` | 数值来源、编号空间及资源职责分别明确 |
| 参考指令与执行语义 | `tests` 下按关卡隔离的参考数据、执行器或预期记录；现有一面文件为 `reference_program.hpp`、`reference_script.*`、`reference_coordinates.hpp` | 独立于生产配方，只供回归，不链接进生产引擎 |

道中预设以 `inline constexpr behavior::Pattern` 命名复用，保存无可变执行状态的移动、单次技能与动画配置。出生位置、HP、分数、掉落、镜像、固定实例种子和外观由 `behavior::Spawn` 单独保存。配方数量由本关实际行为差异决定；Stage 1 的五个配方组合出 222 次实例只是案例，后续关卡不限定为五种，也不要求先扩充敌人类型枚举。

出生掉落编号不能限制于一面实际使用的范围。`sourceItem=-2/-1`分别为无掉落/整关轮换，0…6为小P、分数、大P、Bomb、满P、残机、星点；固定道具不推进轮换计数，仅小/大P在满Power时转分数。Extra8093尾波明确使用5，原生演员固定掉落与脚本道具共用创建器，须保留真实编号并通过出生校验。

多轮攻击、随机后继、准备期与阶段循环使用命名 `behavior::Routine`，提炼共享移动、扫描和发弹辅助函数。不要把每个原始子程序翻译成一个敌人子类，也不要恢复生产用解释器、寄存器、指令分派或按 Sub 编号返回配置的工厂。原编号可留作数值溯源和测试定位；生产控制流使用命名行为。

普通敌人的接入链为：

```text
timeline.cpp 的 StageEvent
→ SpawnActors 携带 behavior::Spawn
→ StageContent::HandleEvent
→ Game::SpawnStageActor
→ ActorPool::Spawn / Actor::Activate
→ Follow 按局部内容帧编排 movement 与 skill
```

## 5. 在内容整理时完成世界单位换算

敌人运动与技能的原作像素坐标只用于解析、分析和测试对照。编写生产事件与配方时，一次性换算为世界坐标常量；生产的出生、运动、插值、随机范围、边界、判定半径及发射偏移均使用世界单位，不再做“像素 → 世界 → 像素”的往返转换。每关先核对源坐标轴、原点、长度比例和时间单位，再落实到项目统一的世界坐标；不能为了适配一关而改变通用组件对所有关卡的单位约定。

下面是当前新典逻辑场地经 Stage 1 验证的换算案例。设 `s = 20/448`、原时钟为 60 Hz；后续关卡只有在确认源坐标和时间约定相同时才能直接沿用。它不替代自机射击、UI 或 ANM 局部坐标各自的比例约定：

```text
世界位置 = ((原X - 192) × s, -原Z × s, 10 - 原Y × s)
世界偏移 = (原偏移X × s, -原偏移Z × s, -原偏移Y × s)
世界速度 = 60 × s × (原速度X, -原速度Z, -原速度Y)
世界加速度 = 60² × s × (原加速度X, -原加速度Z, -原加速度Y)
角速度：弧度/帧 × 60 → 弧度/秒
```

项目世界 +Y 是高度，常规敌人从 +Z 向 -Z 推进，极坐标正角度从 +X 朝 -Z。默认运动位于世界 X/Z 平面；`LiftedPath` 可在同频率下将原编排实际位移等长分配到三维方向，三维插值可改变 XYZ。`Bounds` 保持 X/Z 契约，可另设世界 Y 范围。当前镜像标记只反转最终 X 位移，不能顺带镜像所有攻击角度或发射偏移；其他镜像语义需经原始数据确认后显式建模。光束的全宽与弹池半径还需区分，不能漏掉全宽到半径的二分之一。

Stage 1 示例：第一条原始出生在第 100 帧、位置 `(60,-32,0)`、8 HP，生产事件保存为第 100 帧、平面基准世界位置约 `(-5.89285707,0,11.4285717)`，当前编队高度适配后的入口为 `(-5.89285707,-1.5,11.4285717)`、8 HP，并引用 `kTurningFairy`。初速 `2` 像素/帧换为约 `5.35714293` 世界单位/秒；第 40 帧的角速度 `-0.024543693` 弧度/帧换为约 `-1.47262156` 弧度/秒。出生帧 100 与关键帧 40 均保留原编号。

该实例的固定种子 `3100` 是项目为重放和兼容旧行为保存的值，不是原典出生记录中的字段。之后插入时间轴行也不能隐式重算既有种子。

HP、阈值、分数保持原始点数。道中出生参数显式写入时间轴并由测试核对；Boss 内部技能定义从统一目录读取 HP、预留偏移与超时。不要重新引入生命 ÷25、弹伤害 ÷12 等缩放，也不要把完整时间轴隐藏在目录遍历中。原寄存器恰好等于正预留阈值的过渡可以有零有效HP；保留两者原值，以空血条显示并验证自然接续及受伤阈值，不得补造正HP或用除零结果驱动HUD。

## 6. 区分内容时钟、行为更新与显示帧率

先确认目标源时钟，再整理为项目当前的 60 Hz 内容帧约定。对当前 TH06 新典，源内容帧与项目内容帧同为 60 Hz；如果输入格式或版本的时钟不同，应在内容转写及独立对照中明确换算，不能让某个 Stage 暗中改变通用行为组件的时间单位。

| 时间量 | 当前单位和执行方式 |
|---|---|
| `StageEvent::atFrame` | 开局起算的 60 Hz 绝对内容帧，调度器累计秒数判断到期 |
| 事件 `delay` / 批次 `interval` | 秒；依赖事件完成或上一事件实际开始的语义由调度器定义 |
| `At`、移动关键帧、插值时长、技能延迟、阶段超时 | 60 Hz 内容帧，不能因提高更新频率而把时长减半 |
| 生产敌人/Boss 行为更新 | 默认 120 Hz，每步积分 `1/120` 秒，局部与阶段内容时钟前进 0.5 帧 |
| 当前 60 Hz 原作差分模式 | 显式构造 `UpdateRate::Hz60`，每步推进一个内容帧；新关卡应另有本关参考数据与语义覆盖 |
| 正式战斗与显示 | Game 按 120 Hz 同步关卡、对话、玩家、演员、弹池、Bomb 与碰撞；显示帧率独立，菜单等界面仍按显示时间更新 |

固定更新步保持“应用上一更新步速度 → 执行行为 → 计算下一步速度”的顺序。子行为从零计时，调用期间父时钟冻结，子行为返回后父行为在同一更新步继续。阶段回调后保留未消费的更新步；暂停不推进，重开和销毁释放挂起协程。

`At`允许半内容帧等待，供逻辑发射体逐步检查边界；不能把整数内容帧循环误当120 Hz更新。需要在移动参数和自动姿态更新之后执行的持续逻辑使用`SetStepEffect`：每固定步末、动画/内容时钟推进前执行，可借用当步弹池；Start、Reset和Remove清场自动解除，子调用不解除。Extra第四符已按原生122的末尾回调顺序接入，并另测120.5帧解放、插值落点、根行为切换及清场/复用边界。

独立环境粒子使用`SetAmbientEffects`安装，不能覆盖`SetStepEffect`的战斗回调。环境时钟、相位及视觉随机流属于演员实例，技能交接/Start保留，Reset和Remove清场重置；隐藏时一起冻结。出生须核对构造之后的模板复制链：当前实际current/previous均为0，首步跳过发射，不能沿用构造器中间值previous=-1。芙兰原生6、10/15/17/19对生命的不同检查由Active/Living显式表达，最终退场解除。19的创建参数直接携带世界速度/加速度，独立粒子池不在首步重新随机化它们。视觉随机适配与原生全局随机流的证明边界须继续分开记录。六面同样在Prelude首次放行安装Active，最终符宣告首步切Living，后续准备保留该身份；退场首步停用。隔离入口恢复身份但不清零环境状态，不能把源入口安装点提前至角色创建。

保留随机读取次数与顺序、跨阶段的运动和发弹上下文。已经发出的弹保存独立参数副本；之后修改演员技能配置只影响后续发射。不能因提炼公共函数而多取一次随机数、改变循环首发帧或清空原本保留的状态。

120 Hz 提高了移动和阶段检查的采样频率，数值积分轨迹不要求与 60 Hz 逐点相同。有可信旧实现时，在同频率下验证重构回归；首次移植的关卡则建立独立的源语义或实测记录对照。120 Hz 另行验证更新频率、时长和不同显示帧率下的一致性。提高更新频率也不等于已经加入显示帧插值。

长时限必须同时验证倒计时的数值精度：Extra血痕弹的2000内容帧加速度曾因float剩余秒数多执行一步，现以double保存`Bullet::accelerationSeconds`，初值按帧数/60.0换算；不通过放宽轨迹容差掩盖端点误差。角色的原生Bomb回调安装点由`SkillDefinition::bombReactionFrame`声明；同一角色的133从第0帧安装，其他已接入符卡从120帧安装，不能统一视作准备结束后生效。

## 7. 用事件依赖表达完整流程

每关在自己的 `timeline.cpp` 中显式列出出生、Boss 遭遇、对话或提示事件，保持已核对的绝对帧和同帧顺序，不用初始化 lambda、隐式循环或原始目录自动拼装生产时间轴。事件总数、遭遇次数和阶段数量按目标关卡确定。

分别确认 Boss/对话期间关卡时钟是否继续、到期出怪如何处理、旧批次是否取消，以及存活演员和弹幕是否清场。这些是目标关卡的流程语义，不能默认照抄上一关。如果共享接收端尚不能表达差异，应增加清晰的参数或最小通用接口，并保护已实现关卡的回归，不在 `Game` 中堆叠关卡编号判断。

`WaitDialogueSignal` 显式等待 MSG 的放行序号，零表示对白结束；`ResumeBoss` 只通知现存遭遇推进，不重建 Boss。六面用这两个动作保留对白中的入场和两次恢复，不能合并成一次结尾回调。无台词 MSG 使用 `DialogueMinimumDuration`，不构造占位台词。

`StartDialogue::clearPolicy` 显式区分公共清场与保留世界；MSG 读取本身不等同于原生清敌/清弹。后者须由已核对的行为或事件表达。动画本体中断须交付给 ANM，不能替换为隐藏。协程回拨应同时丢弃已消费等待点，立即调用子行为后返回不得重复等待上一轮。

对白音乐使用`DialogueCueKind::StageMusic`保留0/1/2槽与-1停止，开始帧、战后、跳句和同帧停止/重播均按表序交付一次；不能把整段对白压成“是否播过Boss曲”。普通立绘脚本的创建使用`PortraitStart`，源脚本自然执行入场，不要求后续必有标签1；标签2退场后暂停与标签5最终结束分别保留源含义。文件名顺序不代表表情号，须核对加载精灵基址和MSG选择偏移。Extra的主战前表情2/3、战后0已按这条地址链验证。

需要等待战斗或对话结束的事件使用 `afterEndOf`；异步事件必须带 ID，在实际结束时调用 `EndEvent`。Boss 阶段由目标脚本的生命阈值、击破和超时回调衔接，不能写成预估墙钟时刻；退场行为也属于遭遇生命周期。每张事件表内维护独立 ID 作用域，稳定实例种子也不能依赖后续插入后的表行号。

生存符须把成功条件与伤害击破分开建模；ConfiguredBoss的`survival`只控制实际超时的成功和交接清弹，不能作为受伤或隐藏开关。Game仍按本次尝试的Miss/Bomb判定取得。原脚本若延迟至后继准备清场，应使用明确策略保留该边界，不能统一提前清弹；本体隐藏时主动画及附属动画均不绘制，逻辑时钟、动画与HUD继续推进。

Stage 1 案例：226 条事件包含 222 次小怪出生、两次 Boss 遭遇和两段对话；道中 Boss 在第 1882 帧开始，时间轴继续，到期小怪跳过；第 5092 帧开始战前对话，之后按实际结束衔接关底 Boss 和战后对话。其 Boss 入场保留场上对象、对话开始清除小怪和敌弹。其他 Stage 必须分别确认这些条件，不能复用这两个帧号、226 条事件或四阶段上限。

阶段交接立即设置准备期保护，并同步当帧碰撞后的 HP，避免高显示帧率在下一行为更新前重复推进。HUD 的整组非符/符卡血条与当前阶段生命上限分开维护。素材、动画游标、弹幕与效果的借用者先销毁，再释放关卡资源。

辅助ANM使用Actor的八个独立槽（Boss经公共接口提供），通过命名动画接口分别启动与中断。各槽独立计龄，默认继承本体外观，跨图集时显式绑定当前关卡的VisualId，并与本体进入同一透明排序队列；Game与渲染须同时使用该外观的档案、材质和几何，不能只换游标。辅助动画完成不改变演员行为寿命，复用演员须清空全部旧游标。

普通演员的清场响应由`Spawn::stageClearResponse`显式指定。默认`Defeat`保留置零生命、正常击破与奖励流程；无奖励、无死亡演出的逻辑发射体可在源语义已核实时使用`Remove`，即时销毁协程并释放槽位。不得从隐藏或不可交互自动推导清场策略。`Spawn::visible`保存出生即生效的可见性，避免等待首个行为步才隐藏而闪现；隐藏演员的ANM逻辑尺寸仍可用于回收边界。两项设置在复用时均重置。

## 8. 将忠实保留、三维适配和未实现项分别说明

从 ECL 保留的是波次、内容帧、路径参数、扇形/环形结构、速度层、rank 修正、显现与延迟运动、阶段和掉落等已核对语义。ANM、MSG、数值目录各自提供其对应事实，不能从一类文件推断另一类不存在的字段。

三维适配由项目明确承担。当前 Stage 1 保持普通演员的原 X/Z 队列并按整波设置高度，Boss 在原时序和每步位移预算内保守延拓；弹幕按球面/球冠面积直接采样，逐发扫描均衡覆盖锥内立体角，不采用平面旋转复制。具体参数与密度检查见 `STAGE1_BEHAVIORS.md`，不能当作原典参数或后续关卡默认方案。旧高度坡度方式保留为中性适配差分；玩家使用 6DoF，碰撞、拾取和部分结算规则沿用项目实现。素材的 ANM 局部像素坐标与世界运动是不同层次，不能因使用高清 DDS 就同比放大世界角色、弹体或碰撞尺寸。

台词、等待、BGM、表情等使用 MSG、中文本地化和动画指令核对，并按角色区分分支。当前现代重绘立绘与原始战斗 DDS/ANM 也须标明来源差异，不能声称所有画面都是原包逐像素复现。

对每关分别记录未实现演出、与原生随机序列的差异及结算回退；不在行为重构时无依据地补演出或伪称已还原。一面的记录示例见 [数据对照](STAGE1_REFERENCE.md) 和 [对话对照](STAGE1_DIALOGUE_REFERENCE.md)，共享接口见 [素材接口](NATIVE_BATTLE_ASSETS.md) 与 [数值目录](NATIVE_COMBAT_DATA.md)。新关卡应补自己的记录，不能用一面的覆盖说明替代。

## 10. 后续更新的操作顺序

每个新 Stage 依次完成：固定输入与哈希，提取并审阅记录，确定目标难度和入口的可达控制流，建立独立基准，整理单位和状态约定，提炼通用参数组件与本关配方，显式编写事件及异步依赖，接入素材/对话/数值，运行本关差分与实际游戏回归，最后清理临时依赖并同步文档。

在 `src/stages/stageN/` 组织内容、时间轴、行为、Boss、素材和对话，在 `CMakeLists.txt` 登记源码；通过 `src/stage/catalog.*` 登记内容工厂、关卡编号及对应模式的选择/存档映射。整关练习列表仅有1～6面槽位；符卡练习通过`SpellPracticeStage`单独映射0…6，Extra使用第七槽及UI难度4，不扩充主线整关成绩。Extra单符工厂仅接受119…131与内部Normal；132…134仍为遭遇记录。验证尚未完成时保留未开放状态，不因数值或素材已导入就将 `DataOnly` 改为可玩。

每关交付时应留下以下记录，具体文件名可沿用 `STAGEN_REFERENCE.md` / `STAGEN_BEHAVIORS.md` 的形式：

| 记录项 | 应提供的内容 |
|---|---|
| 输入与范围 | 游戏/数据版本、关卡、难度、角色和入口、哈希、目标文件 |
| 控制流与数量 | 可达子程序、出生请求、遭遇、阶段和对话分支，数量的独立来源 |
| 转写与适配 | 原数据到通用组件/命名配方的映射、单位换算、时钟和清场规则 |
| 证据与边界 | 参考基准来源、实际运行的测试、未实现项、项目适配和误差约定 |
| 接入与生命周期 | 内容/素材注册、可玩入口、事件完成条件、资源释放及存档编号 |

最终代码应同时回答四个问题：某个常量来自哪里，某个时刻由哪个时钟决定，某个实例由谁持有并销毁，行为一致性由哪项独立证据验证。缺少其中一项时，应继续补齐依据，不能仅凭“画面看起来相近”结束移植。

附着演出使用`Actor::AttachEffect`，输入无量纲世界轴、世界目标半径及RGBA；同一演员的已有轨道共享最后一个目标半径。演员持有`AttachmentAnchor`，请求和粒子只保存弱引用，不能借用演员地址或延长演员寿命。Game每个固定战斗步先更新演员中心，再推进效果池；Start/正生命阈值交接保留附着，隐藏、生命归零、超时、Remove、Reset和销毁释放，冻结轨道并按16内容帧淡出。碰撞触发的Boss生命归零须在交接当步释放，不能等下一次Actor::Tick。512槽普通回收/复用保留轨道半径与相位，整池Clear才归零；项目满池仍丢弃视觉请求，不据此宣称原生尾部哨兵行为等价。

## 11. 已明确批准的134积分精度例外

134严格差分发现原作float累计和世界float累计在回收边界两侧相差约8.3e-5世界单位，却引起一帧离散分歧。用户明确批准仅积分内部保留原作float数值模型、全部公开状态继续使用世界单位；对应`movement::State::EnableFloatIntegration`仅在134两层使魔启用。格原点/格长配置为世界量，不开放内部坐标，不恢复`movement::Space`或把原始变量/脚本分派引入生产。外部位置修改重基准，插值退出，实例和池复用各自独立；其他行为仍按既有默认积分，不能因本例自动推广。保留原位置/速度容差与离散活动位精确比较，新增关卡若出现同类冲突仍须先定位数值证据及适配边界。

## 12. 完整遭遇中的准备血条与归零分流

`SkillSlot::onDamage`沿用阈值/一般伤害出口，新增可选`onDefeat`只在原生命归零或实际Defeat回调时使用，缺省仍沿用onDamage；真实超时始终优先走onTimeout。Extra的38…81在114/116进入当前符卡，但108跳到下一包装，因此不能只按单符测试顺序拼接。Jump索引、引用合法性与复制生命周期按原约束校验。

准备仍可作为独立命名技能使用，其生命、时限和回调完整执行；`omitHealthBarSegment`显式声明该次使用不占HUD段，不按生命/符卡类型自动推断。未省略的每次使用仍恰好绑定一段，段比例须为正且总和为1；被省略的使用若仍被段引用则拒绝。这样Extra的零有效HP生存前奏、重复6000生命的最终准备及210帧后继准备无需虚构占位血条比例，阶段数/剩余血条仍按源126保持10/3阶段。
