# koumakyou 项目 NABCD 需求分析

分析日期：2026 年 10 月 19 日。

本文以项目的最终产品目标为分析对象：**对《东方红魔乡：新典》的全流程关卡进行 3D 化改造，让玩家以第一人称视角完成贯穿完整游戏流程的空间弹幕冒险。** 文中的产品能力与交付方式均围绕这一目标论述；现有第一面原型用于验证技术路线与交互方案，不构成最终产品的内容边界。用户动机、体验收益与推广效果属于需求假设，需要通过后续调研和试玩验证。

## 一、项目概述与产品定位

`koumakyou` 计划将《东方红魔乡：新典》从二维俯视弹幕射击改造为第一人称三维弹幕射击游戏。玩家将沿原作关卡顺序推进，在三维空间中探索安全路线、应对各关敌人与 Boss、挑战符卡，并经历从开场到最终结局的完整过程。

全流程改造以原作完整关卡目录为内容边界：主线覆盖连续关卡、道中与 Boss 战、对话、阶段转换和结局；原作中的独立追加关卡按其独立流程与进入条件组织。角色、机体和难度作为贯穿各关的玩法维度统一适配。具体关卡清单与规则应在详细设计中依据原作核对，避免把主线通关和其他独立流程混为一条时间线。

改造需要保留原作的故事脉络、角色辨识度、音乐氛围、关卡节奏和符卡特色，并围绕三维视角重新设计移动、瞄准、威胁提示及难度平衡。其最终价值在于让玩家用新的交互方式完整经历红雾异变，形成兼有熟悉感与探索感的游玩体验。

**产品定位：面向东方爱好者与空间射击玩家的《东方红魔乡：新典》全流程第一人称 3D 改造作品。**

## 二、N：Need——为什么要做这个软件

### 2.1 最重要的需求

**核心需求是：让希望以新方式重温《东方红魔乡：新典》的玩家，能够亲自置身弹幕与场景之中，完整经历红雾异变的冒险和挑战。**

对于熟悉原作的玩家，角色、音乐、关卡和符卡已经构成一段有记忆点的游戏经历。他们可能希望从新的视角重新理解这段旅程：当弹幕拥有纵深、敌人出现在眼前、自己能够升降与转向时，熟悉的关卡会带来怎样的变化？项目通过完整的三维改造回应这种重温经典并获得新体验的动机。

完整流程是这一需求的重要组成部分。单场 Boss 战可以展示新鲜感，而从开场逐步深入、面对不同风格的敌人与符卡、最终完成通关，才能形成连贯的成长与情绪积累。玩家需要能够把前面学会的空间判断运用到后续关卡，感受到自己的掌握程度随旅程推进而提高。

因此，项目首先要回答的是“玩家为什么愿意以第一人称重新走完这段旅程”。弹幕系统、场景渲染、关卡脚本与练习模式，都是服务于这一核心需求的手段。

### 2.2 目标用户与使用场景

| 用户群体 | 典型场景 | 主要诉求 |
| --- | --- | --- |
| 希望重温经典的东方玩家 | 按关卡顺序重新经历红雾异变，比较熟悉符卡在三维空间中的变化 | 保留原作辨识度，获得足以支撑完整通关的新体验 |
| 喜欢弹幕研究与高难度挑战的玩家 | 研究各关路线、反复练习 Boss 与符卡，追求更少失误和更高成绩 | 规则清楚、挑战公平、策略可学习，能持续提升表现 |
| 对东方题材感兴趣的键鼠射击玩家 | 通过第一人称操作进入弹幕玩法，逐步完成整部作品 | 操作直观、引导充分，能理解故事与关卡推进 |
| 喜欢经典游戏改编和三维玩法的玩家 | 体验二维规则转化为三维交互后带来的变化 | 改造具有实际玩法意义，并有完整内容支撑 |

教学展示与开发学习是项目的附加使用场景。产品的核心价值仍应通过玩家能否享受完整旅程来评价。

### 2.3 用户痛点与需求成立的条件

围绕这一核心需求，需要解决三个相互关联的问题：

1. **熟悉内容需要新的参与方式。** 对愿意尝试改编的玩家，三维移动应产生新的观察与躲避策略，使重玩各关都有探索价值。
2. **新视角需要可理解的规则。** 第一人称视野和纵深会增加信息判断负担。玩家需要辨认危险方向、距离和攻击时机，理解受击原因，并通过练习改进。
3. **完整旅程需要持续的节奏与成长。** 不同关卡应有可辨识的环境、攻击主题和挑战递进，让玩家感受到推进与突破，愿意从开场坚持到结局。

需求验证应覆盖初次体验、跨关推进和完整通关三个层次。除观察玩家是否觉得新鲜，还应了解其是否愿意继续下一关、是否能形成策略，以及通关后是否愿意重玩或练习。

## 三、A：Approach——如何满足这一需求

### 3.1 以完整关卡流程组织改造

以原作流程为骨架，梳理每一关的道中波次、场景主题、道中 Boss、关底 Boss、符卡阶段、对话、音乐切换和结算关系，建立统一的内容改造规范。各关可以分别制作和验证，但最终应连接成连续可玩的完整流程。

改造既要关注单关内部，也要关注跨关体验：关卡结束如何衔接下一关，残机、Bomb、火力与成绩如何延续，角色路线与难度如何影响全程，以及失败、重试与结局如何形成完整反馈。详细设计应明确这些规则，并保持同一轮游戏中的一致性。

这样，玩家获得的是一段不断推进的旅程，各关的完成也成为整体通关目标的一部分。

### 3.2 将二维弹幕规则转化为三维策略

以第一人称观察和三轴移动为基本交互，提供射击、低速移动、Bomb 等操作。摄像机视点与玩家判定位置保持一致，让玩家能够建立视觉位置与碰撞结果之间的联系。

对每类敌人与符卡，先提取其核心特征，例如旋转、包围、瞄准、交叉、封路或节奏变化，再选择合适的空间展开方式。改造应让玩家仍能辨认攻击主题，同时运用高度、侧向和纵深进行应对。

不能把全部二维轨迹简单铺进三维场地。对于可能被固定高度或纵深位置长期绕过的攻击，需要调整空间覆盖、瞄准方式或移动约束；对于第一人称下难以观察的攻击，需要补充预警或调整攻击节奏。每项调整都应兼顾符卡特色、躲避空间与可学习性。

### 3.3 用场景与信息设计维持沉浸感和公平性

根据各关主题设计三维环境、空间参照、入场与转场，使场景变化与故事推进相互配合。角色、音乐、对话与符卡演出共同保留原作氛围，让玩家在视角变化后仍能理解自己身处旅程的哪个阶段。

同时建立统一的空间信息表达：通过清晰的弹幕外观、深度线索、危险方向提示、攻击预警与 Boss 状态，帮助玩家判断威胁。提示形式应通过试玩选择，避免画面信息过多而遮挡真正需要观察的弹幕。

全流程必须保持稳定的视觉约定与判定规则，不能让玩家每到一关都重新猜测相似攻击的含义。

### 3.4 建立从入门到精通的体验路径

| 目标产品方案 | 对应问题 | 在完整流程中的作用 |
| --- | --- | --- |
| 操作引导与渐进的前期关卡 | 初次接触第一人称空间弹幕时学习负担较大 | 先建立观察、移动与基本躲避能力，再引入组合挑战 |
| 标准模式与无限残机挑战模式 | 不同玩家对失败成本和挑战强度的接受程度不同 | 支持严格通关与持续体验两种目标，分别评价成绩 |
| 关卡、Boss 与符卡练习 | 后期难点反复尝试时，前置流程占用时间 | 让玩家集中解决难点，再返回完整流程验证成果 |
| 灵敏度、键位、音量与显示设置 | 不同操作习惯和设备影响体验 | 减少长流程游玩中的操作与视听负担 |
| 按角色、难度和模式区分的进度与成绩记录 | 玩家需要明确自己完成了什么、下一步挑战什么 | 支持通关目标、路线探索和重复挑战 |

这些内容按最终产品方案描述。练习入口、解锁规则、成绩口径及记录维度需要在详细设计中统一，确保练习成绩与正式全程成绩能够正确区分。

### 3.5 以统一框架支持全部关卡的制作与交付

采用统一的关卡调度、敌人行为、弹幕、碰撞、资源管理与界面框架，将各关的场景、脚本和演出作为内容组织。技术实现沿用 C++20、raylib 与跨平台 CMake 工程，并面向 Windows 和 macOS 交付。

制作上可按“代表性关卡验证—逐关改造—全流程联调—整体平衡”的顺序推进。第一面用于验证基本交互，后续关卡用于检验框架能否承载不同攻击主题与复杂度；全流程联调则重点解决跨关状态、资源切换、累计难度和结局衔接。

阶段划分服务于实现完整产品。后续关卡属于既定目标，应按统一质量要求推进；性能指标需在不同配置设备与高负载场景中实测后确定。

## 四、B：Benefit——最终产品给用户带来什么好处

### 4.1 重新经历完整的红雾异变

玩家能够把熟悉的角色、音乐、符卡与场景串联为一次第一人称冒险。从早期的观察与适应，到中后期的策略积累，再到最终突破，完整关卡流程使新视角带来的体验能够持续展开，并在通关时形成完成感。

对于原作玩家，好处在于用新的方式重温已有记忆；对于新玩家，好处在于通过自己熟悉或愿意学习的空间操作，接触这一作品的角色与弹幕文化。

### 4.2 获得新的躲避思路与操作乐趣

三维移动使玩家可以综合高度、方向、距离和时机选择路线。不同符卡对应不同空间问题，玩家通过观察与实践找到应对方法，获得理解攻击、执行策略并成功突破的成就感。

这种收益依赖有意义的空间设计。三维改造应让玩家感受到更多可理解的选择，并保持失败与决策之间的清晰联系。

### 4.3 以适合自己的节奏完成挑战

标准模式提供完整通关的目标，无限残机挑战模式允许玩家持续接触后续内容，分层练习则减少重复前置流程的时间。玩家可以先体验全貌，再集中训练薄弱环节，最后回到正式流程检验进步。

随着角色路线、难度、关卡与符卡记录逐步积累，产品能够提供从“看到结局”到“掌握全程”的持续目标，支持不同投入程度的玩家长期游玩。

### 4.4 收益与验证方式

以下为目标收益与建议验证方法，不代表已有调研结论。

| 目标收益 | 观察重点 | 验证方法 |
| --- | --- | --- |
| 熟悉作品得到新的完整体验 | 原作辨识度与三维改造价值能否同时成立 | 邀请原作玩家评价不同阶段的体验，并举出具体变化 |
| 空间移动带来实际策略 | 高度与纵深是否产生有效选择，各符卡是否存在明显绕过方式 | 观察多种路线，记录玩家策略、受击原因与异常安全位置 |
| 关卡推进形成成长感 | 前期学习是否帮助后期应对，难度是否存在突变 | 分阶段试玩与连续游玩结合，记录卡关点和学习过程 |
| 完整通关具有吸引力 | 玩家是否愿意继续下一关并达到结局 | 记录继续游玩、主动退出与通关情况，访谈对应原因 |
| 练习与记录支持重玩 | 玩家是否愿意主动练习并回到全程挑战 | 观察练习选择、再次挑战行为与策略变化 |
| 长流程体验稳定舒适 | 操作负担、视听不适、卡顿和资源切换问题 | 在目标系统和不同设备上进行连续游玩测试 |

产品需要重点验证“新鲜感能否转化为持续游玩的意愿”。如果部分关卡令人困惑或疲劳，应修正这些环节的空间信息、时长和难度衔接，使整段旅程保持吸引力。

### 5.1 差异化定位

本项目拟形成的差异是：**以《东方红魔乡：新典》的完整关卡与故事为内容骨架，以第一人称三维移动重构弹幕躲避，并以逐关成长和符卡练习支持完整通关与持续挑战。**

这使产品同时回应经典重温、空间操作与完整冒险三方面的动机。全流程覆盖提供连贯的体验，三维弹幕带来新的策略，练习与记录则支持玩家逐步掌握这些策略。

这一定位是产品设计方向，不能据此宣称市场首创或优于所有同类作品。实际竞争力取决于玩家是否愿意选择并完成这段旅程。

### 5.2 竞争挑战与应对

第一，原作的二维视角便于同时观察较大范围的弹幕，第一人称需要通过空间提示与攻击设计建立相应的公平性。第二，经典内容具有明确的玩家预期，改造需要解释哪些特征被保留、哪些规则因三维交互而调整。第三，全流程包含不同风格和强度的关卡，需要保证品质与难度曲线一致。

应对策略是统一改造原则、逐关验证符卡特色、开展连续通关测试，并持续邀请原作玩家与射击玩家参与反馈。竞争优势应建立在完整且稳定的游玩体验上。

## 六、D：Delivery——如何推广并交付最终产品

### 6.1 核心传播信息

围绕最终目标，建议使用以下介绍：

> 以第一人称重新走进红雾异变，在三维弹幕中穿行，挑战《东方红魔乡：新典》的全流程关卡。

展示时应将全流程旅程、各关特色与空间躲避结合起来，让观众同时理解“能经历怎样的冒险”和“操作会发生怎样的变化”。发布阶段性版本时，应明确标注已开放内容与最终目标的区别。

### 6.2 分阶段推广与交付

| 阶段 | 面向人群与渠道 | 主要内容 | 期望效果 |
| --- | --- | --- | --- |
| 概念验证与早期试玩 | 原作玩家、键鼠射击玩家、校内社团与课程展示 | 代表性关卡实机、玩法介绍、试玩说明与反馈入口 | 验证核心需求，发现空间交互和原作还原方面的问题 |
| 全流程制作期间 | 东方、弹幕与独立游戏社区，B 站等视频平台，项目开发日志 | 各关改造展示、原作与三维版本对照、符卡攻略及制作进展 | 建立对完整旅程的预期，吸引持续参与的试玩者 |
| 完整版本发布 | 项目主页、具备相应分发条件的游戏下载渠道与兴趣社区 | 全流程预告、完整版本、系统要求、操作引导与更新说明 | 让感兴趣的玩家顺利获取游戏并完成首次体验 |
| 发布后的持续传播 | 玩家社区、攻略与实机视频、版本更新记录 | 通关心得、不同角色与难度挑战、符卡路线分享与问题修复 | 支持重玩、交流与玩家推荐 |

以上为推广规划，不代表已经发布或建立合作。可优先采用实机内容与社区反馈驱动的方式，随着完整流程逐步成形扩大传播范围。

### 6.3 让用户顺利从关注走向通关

目标路径为：**看到完整玩法介绍 → 理解三维改造的价值 → 获取对应平台版本 → 完成操作引导 → 推进各关 → 练习难点 → 完成通关 → 重玩或分享。**

产品主页需要清楚说明改造目标、关卡范围、角色与难度、模式区别、平台要求及获取方式。Windows 和 macOS 交付应提供可直接运行的游戏包，并验证安装或解压、首次启动、输入、资源加载、设置保存与完整流程运行。

游戏内的引导、关卡推进、失败反馈与练习入口需要共同承接推广承诺。玩家因“完整重温红雾异变”而来，就应能够清楚知道下一步如何继续，并在遇到难点时找到适合的练习方式。

资源方面，应建立游戏素材、音乐、字体与第三方组件的来源及分发条件清单，为公开交付安排相应的授权或替代资源方案。具体收费与渠道方案在分发条件明确后确定。

### 6.4 推广效果评价

推广评价围绕“关注—获取—启动—持续推进—通关—重玩或推荐”展开：

- **兴趣是否形成**：观众能否准确理解第一人称改造与全流程目标，是否愿意查看介绍或获取游戏。
- **交付是否顺畅**：玩家能否在目标平台成功启动，能否完成操作引导并开始正式流程。
- **体验是否承接承诺**：玩家是否持续进入后续关卡，在何处退出或卡关，原因与操作、难度、内容或运行问题有何关系。
- **价值是否持续**：玩家是否完成通关，是否主动练习、尝试其他路线或难度，是否愿意分享与推荐。

这些指标用于设计后续观察和自愿反馈，不代表已经建立统计系统或获得运营数据。早期收集定性反馈，完整版本形成后再评价跨关推进、通关与重玩的整体表现。
