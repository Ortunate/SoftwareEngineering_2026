# 红雾幻想 3D 第一人称空间弹幕演示版设计

本文记录现有实现。面向《东方红魔乡：新典》全流程 3D 改造的目标系统设计见[软件设计说明书](SOFTWARE_DESIGN.md)，产品需求见[NABCD 需求分析](course/NABCD.md)。

## 1 设计目标

项目实现一个可在 Windows 和 macOS 运行的真正三维弹幕射击演示。战斗发生在尺寸为 20×20×23（X×Y×Z）个逻辑单位的长方体内部，Z 为长轴，玩家可以沿 X、Y、Z 三轴移动并自由观察。摄像机位置与玩家碰撞球中心始终完全一致，因此画面视点就是判定点。

当前战斗范围为《东方红魔乡：新典》Normal 一至六面及完整主线结局，开放灵梦／魔理沙四种御札。事件时刻、敌机航线与攻击参数使用本机新典的 Normal 帧脚本，保留三维操作与深度扩展。天空盒由程序生成，对话立绘为现代重绘；战斗角色、弹体和道具直接读取新典 DDS/ANM。

```text
├── README.md

│   └── DESIGN.md
├── src/
│   ├── main.cpp

│   ├── core/                    # 定长对象池
│   ├── gameplay/actors/         # 玩家、敌人与 Boss
│   ├── gameplay/bullets/        # 弹幕类型、弹池与方向算法
│   ├── gameplay/combat/         # 碰撞、射击与阶段推进
│   ├── gameplay/effects/        # 共用角色入退场表现与快照池
│   ├── gameplay/items/          # 掉落分布与道具生成、拾取
│   ├── platform/                # 窗口级输入法策略与原生桥接
│   ├── render/                  # 世界、精灵与 UI 绘制
│   ├── resources/               # 素材清单、加载资源与所有权
│   ├── stage/                   # 关卡接口、注册与时间轴
│   └── stages/                 # common 公共素材及 stage1～stage6 独立内容
├── assets/runtime/common/      # 天空盒、着色器、标题 BGM
├── assets/runtime/stages/       # 一至六面立绘与音乐
├── assets/runtime/endings/      # 原生高清结局背景与结局曲
├── assets/runtime/battle/native/ # 全部原始战斗 DDS/ANM
├── assets/source/              # 当前立绘的原始参考、来源及生成提示词
├── tools/                      # 资源生成与性能测量
└── tests/                      # 设置、玩法、关卡测试
```

依赖方向为 `main -> Game -> StageContent/StageDirector/behavior::Actor/Boss/BulletSystem/DropSystem/AssetManager`。各关 `StageContent` 提供事件、资源、对话与 Boss 工厂；普通演员由 `SpawnActors` 携带 `behavior::Spawn` 直接接入 `ActorPool`，不经过敌人类型注册或工厂。`behavior::Actor` 组合移动、技能和生命周期状态；`BulletSystem` 管理生成后弹体的运动和回收。`DropSystem` 按原始 item 字段执行整关轮换与掉落。`AssetManager` 独占 GPU/音频资源，`SpriteRenderer` 借用行为演员、Boss 与资源绘制。

普通模式前五关结算后按目录异步进入下一关，保留自机库存、火力、累计分数与统计，本关奖励计数归零；练习和预览单关结束。切关先清除全部素材借用者，再释放旧关资源，加载完成才推进新关时钟。逐关内容及验证见 `STAGES_2_6_REFERENCE.md`。完整通过一至六面后，末关安全收尾并异步加载六种结局之一，播放结束进入最高分选存和命名，不接制作人员演出；条件、资源与存档见 [ENDING_REFERENCE.md](ENDING_REFERENCE.md)。

素材按生命周期分组：程序启动时加载通用天空盒和标题 BGM；Stage 1 开始时加载角色、弹幕、对话立绘、战斗着色器以及道中和 Boss BGM。胜利或失败先进入 `Finishing`，停止战斗并播放剩余退场，效果池清空后停止关卡 BGM、释放专属素材，再进入对应结局、练习出口或结算。返回菜单或重开立即丢弃效果，再卸载或替换关卡资源；菜单素材在程序退出时释放。露米娅的世界精灵使用 stg1enm2，立绘仍使用现代重绘 PNG，两者独立。原始战斗图集按需缓存，未使用素材也可通过目录编号加载；接口约定见 `NATIVE_BATTLE_ASSETS.md`。通用音效清单包含菜单、战斗和原始帧脚本音效，按同一生命周期加载和释放。截图模式不初始化音频设备，因此只加载图形素材。

交互开局、重开及练习先进入 `Loading`，只使用通用字体绘制“少女祈祷中”。`AssetManager::BeginStageLoad` 按 PNG 路径/原始图集编号去重，`AdvanceStageLoad` 每次只后台读取并解码一张图片，在图形主线程每帧最多上传一张纹理，随后释放 CPU 像素。任务不访问 GPU、音频或资源缓存，清单字符串须保留到完成或取消；取消及析构等待当前单张图片解码完成，再释放未上传结果。全部素材就绪后绑定外观与音频、初始化本局，从下一帧开始战斗计时。失败时可按确认/取消返回首页。静默预览保留同步入口，普通截图等待异步加载完成后才推进战斗。

加载集成测试验证动画变化、实际加载进度、关卡时钟冻结、重开/符卡练习、取消和缺失素材的清理：

```bash
cmake --build build/macos-debug --target koumakyou_loading_tests
./build/macos-debug/koumakyou_loading_tests output/loading-review
```

## 3 空间与第一人称摄像机

战斗视口覆盖整个窗口，不再使用原作整幅侧栏背景、固定窄内窗或 16:9 留边。纵向视角保持 72 度，按实际窗口宽高比构造透视投影，角色世界尺寸与判定保持原值。原生窗口按实际 framebuffer 尺寸设置 OpenGL viewport/scissor，离屏目标沿用纹理像素，避免 Retina 双重缩放。

`GameplayLayout` 以窗口逻辑像素定义浮窗与演出区域：左上为关卡编号、中文名、副标题和模式，内容来自 `StageContent::DisplayInfo()`；右上为得分、最高分、残机/MISS、Bomb、Power、Graze 和点数。紧凑窗口缩减留白和状态行间距。Boss 信息在宽窗口的两侧卡片之间显示，窄窗口移到其下方，矮窗口移到下方；浮窗不接收鼠标，也不裁掉底下的场景。准星始终在窗口正中。普通反馈位于底部并为 FPS 留出一行。

`gameplay_hud.cpp` 统一绘制卡片、Boss、对话和符卡演出。对话框居中贴底，立绘等比锚定左右底角，仍使用各差分的裁剪与逐句表情；符卡全身差分沿窗口右缘滑入，名称独立显示，时序不变。演出期间降低侧边 HUD 强调。原侧栏贴图继续作为参考素材保留，运行时不再加载其纹理。生命周期测试检查各边渲染覆盖、转动镜头时左右边缘变化，以及原生窗口和离屏目标；布局测试检查多尺寸下浮窗边界与互相避让。

Boss 浮窗按新典录屏将 Enemy、血条和倒计时放在同一行，符卡名称单独置于下一行；Enemy 数字表示当前组之后剩余的血条组数。阶段 config 显式指定每段绑定的技能、固定比例和 RGBA 颜色，段数不限制为两段或三段。Boss 解析并通过 `DrawHealthBar(area)` 绘制，Game HUD 只提供布局区域；`HealthBar()` 快照仍用于检查，比例不从技能 HP 自动推导。当前已完成技能为空段，后继技能为满段，当前技能按自身可消耗生命填充。露米娅第一组为非符 6100＋符卡 900（总计 7000 原作 HP），第二组为非符 6700＋符卡 800（总计 7500）；粉色符卡段分别固定占 900/7000 与 800/7500，白色非符段从右端消耗，进入符卡后继续消耗左端粉段。道中只显示白色单段，退场隐藏；战斗伤害、阶段阈值和超时不受展示快照影响。第一张符卡结束时立即交接第二组完整生命，准备期禁止碰撞重复推进，避免高帧率下先于下一次 120 Hz 行为更新将低血量占位判为非符结束。倒计时按原作整秒向下取整，在 20/10/5 秒切换蓝、紫、粉、红色提示。`koumakyou_lifecycle_tests <截图前缀> --boss-hud-only` 验证五种横竖屏下的真实分段颜色，以及 30/60/120/240 FPS 各渲染帧间隙的实际击破、超时交接和第二组非符六光束。

对话立绘的发言状态由 `DialogueMotion` 管理。一面按展开后的原生指令时间轴重建：入退场各 30 帧，发言强调的 Alpha 在 16 帧内变到 255/128，自机位置 16 帧、对手位置 30 帧，沿二次减速曲线过渡。重绘人物仍等比贴齐窗口底角，非发言者缩至 90% 并微移；原生退场单独向侧边移出。加载器在 `dialogueCrop` 取景内扫描 Alpha >16 的可见边界并缓存，排除透明留白和近透明修复残留；同步与后台加载共用计算，完整纹理及符卡取景保留。窗口缩放不缓存旧像素位置，绘制不推进动画，暂停冻结。对话按角色选择原文及差分；句中换脸、名牌输入锁、Boss 音乐与末尾等待均由原脚本数据决定，跳句不会继承错误状态。空指令表的其他关卡仍可使用通用逐句强调。`koumakyou_lifecycle_tests <截图前缀> --dialogue-only` 检查真实立绘、透明混合、暂停、两位自机战前/战后每句的横竖屏画面及退场；原文、编号与帧数见 [一面对话对照](STAGE1_DIALOGUE_REFERENCE.md)。

- 长方体逻辑边界为 X/Y ∈ `[-10,10]`、Z ∈ `[-11.5,11.5]`，长宽比约 1.15。
- 玩家碰撞中心为 `Player::position`。
- 每帧强制执行 `camera.position = player.position`。
- 鼠标控制 yaw 和 pitch，pitch 被限制在约正负 83 度，避免摄像机翻转。
- W/S 沿观察方向移动，A/D 横移，Space 上升，Left Shift 下降。
- 玩家不能越过长方体六个表面。

所有战斗键位都保存在 `KeyBindings` 中。OPTIONS 一级页面调节 FPS、BGM 音量、鼠标灵敏度，按键设置二级页面编辑绑定。键盘沿用 raylib 键码，鼠标使用 1000+按钮编号（0～6）避免编码冲突。十个动作各只有一个入口，统一参与冲突交换；Focus 默认右键、射击默认左键、Bomb 默认 F、暂停默认 P。录入时 X / Esc / 右键用于取消，F3～F6 保留；已有战斗绑定不受 UI 规则影响。录入需先释放激活弹窗的确认键及所有鼠标按钮，避免误录。

`main` 在 `InitWindow` 后、处理首帧事件前调用 `DisableWindowInputMethods(GetWindowHandle())`，整个游戏窗口关闭输入法合成，成绩命名接受可打印 ASCII。Windows 用 `ImmAssociateContextEx(HWND, nullptr, 0)` 解除本窗口的 IMM 上下文，链接 `imm32`；macOS 获取 `NSWindow.contentView`，给该实例设置无新增 ivar 的运行时子类，将 `inputContext` 返回值设为 nil，`interpretKeyEvents:` 仅把可打印 ASCII 交回原 GLFW `insertText:` 字符回调，不启动输入法解释。子类保留原 GLFW `keyDown:`、`keyUp:` 与 `flagsChanged:`；当前 raylib 5.5 内置 GLFW 在调用文字解释前已报告物理按键。升级窗口后端时必须复核这一次序。类由 Objective-C runtime 持有直到进程结束，不替换原 GLFW 类的全局方法，也不持有已销毁的窗口。重复调用安全，窗口重建后重新应用；该策略不修改系统输入源；命名页单独消费字符队列，并解除 WASD／Z／X／Space 的菜单别名，确认切页时清空旧字符。

开局流程实机对照新典：Start → 难度 → 主人公 → 御札 → 模式 →「准备好了吗？」→ 加载页。`StartSetupStep` 显式区分各步骤，`UpdateStartSetup` 只在 Ready 收到新的确认事件时启动关卡；取消逐级返回，普通开局 Ready 退回模式，整关练习 Ready 退回关卡，保留所有已选内容。通用组件位于独立的 `src/ui` 模块（`koumakyou_ui` 目标），仅依赖 raylib；页面保留业务路由、素材所有权和存档，公共接口及示例见 `UI_MODULE.md`。所有交互页面共用 `ui::MenuInput`：WASD / 方向键切换、鼠标移动选择、Z / Space / Enter / 左键确认、X / Esc / 右键返回。设置数值行保留左右调整，点击左箭头减小、行内其他位置增大。鼠标静止不覆盖键盘选择，空白点击不确认，返回优先于同帧确认；首页返回只选中 Quit。首页选择在本次运行中保留，离开子页或战斗后仍选中上次入口，首次启动默认 Start。所有界面统一在窗口底部显示 `CommandBar` 的当前功能按键，战斗提示读取自定义绑定；页面控件为横条预留空间，3D 场景仍铺满窗口。开局各页点击可用选项直接推进，移除边角按钮，只有最终确认页的 START GAME 能启动加载。音乐页按标题、六面道中/Boss、Extra三槽和结局顺序导航全部17首BGM，每页六首，左右键/A、D与公用箭头切换页面，上下键/W、S与滚轮选择曲目，翻页不自动播放，首页/末页不循环；试听仅按需持有一条独立音频流，重复确认不重启，返回时释放，Option／Score／Music Room 及改键子页移除返回按钮，统一使用返回键；普通浏览 Score 使用返回键退出，通关保存后可确认返回，制作信息保留确认返回；暂停与结算选项共用键鼠选择。对话确认推进一句、返回打开暂停；加载失败接受确认或返回回到首页。Practice Start 在模式后增加 Stage 页，再进入最终确认。右侧六行显示当前标准/挑战模式的关卡最高分，一至六面均可选，未注册关卡置灰且键鼠均跳过；竖屏列表放在人物信息下方的右侧，并将模式/御札摘要下移，避免与难度札重叠。Stage 与 Ready 共享列表、人物及摘要的连续权重。当前实战开放 Normal、灵梦／魔理沙四种御札与一至六面；两位主人公均可在最终确认后实际开局，使用各自的射击和副机素材。其他难度以未开放札显示，不触发开局。难度页展示四张札，人物页及后续选择保留现代重绘前景、放大的淡色背景、难度札和能力评级；模式及确认页逐步显示御札与模式摘要，最终确认采用新典的横向红黑遮罩。`StartSetupLayout` 让绘制与点击共用屏幕区域，横屏与竖屏分别排布人物和选项，立绘保持等比。选中强调沿用 `MenuMotion`，跨页展示由 `StartSetupMotion` 统一管理：首页与各步骤在 0.30 秒内缓入缓出，快速确认或返回从当前混合权重继续，输入始终即时生效。人物、能力评级和已选御札按相关页面权重之和持续显示，Normal 难度札从列表连续移动到人物页左下角；最终确认横幅淡入并在返回时平滑退出。首页进入难度页时四张札每隔 0.07 秒依次启动 0.38 秒的滑入和淡入；各层原有 Alpha 相乘，绘制及窗口缩放不推进时钟。过渡直接按当前窗口布局绘制，不缓存屏幕截图，也不创建额外离屏纹理。符卡练习使用独立关卡页及同页符卡/难度两栏，键盘确认和返回递进操作焦点，鼠标悬停即可联动并直接跨栏；两列独立保存强调，焦点切换不重播页面进场，难度确认后直接加载；横向键和人物箭头在每一层切换四种角色／御札组合，不覆盖普通开局的模式记忆。完整 131 个变体由只读目录提供，未实现项保留原文并置灰。双角色前后层素材与交互见 `START_CHARACTER_SELECTION.md`，符卡练习详见 `SPELL_PRACTICE_REFERENCE.md`。

FPS 上限提供 30、60、120、144、240 和 Unlimited 六档，通过 raylib 的 `SetTargetFPS` 即时应用。窗口未强制启用垂直同步，因此各档位不会被 VSync 设置覆盖。

设置持久化由独立的 `settings` 模块负责。程序启动时先使用 `std::filesystem::exists` 检查当前运行目录中的 `koumakyou_settings.cfg`：文件不存在时构造默认 `GameSettings` 并创建文件；文件存在时逐项读取 FPS、BGM 音量（0～100）、灵敏度（10～300，100 为原速度）和 `KeyBindings`。修改后立即保存 version=8 配置，新增 last_character（0 灵梦／1 魔理沙），校验数值范围及键位唯一性；旧配置默认灵梦，角色与角色内的两种御札分别保存。旧版默认低速移动（version=1 的 C 或侧键）、射击 Z、Bomb X 升级为右键、左键、F，备用字段移除，其他自定义主键保留；新默认已被其他自定义动作占用时保留该旧主键。AssetManager 把音量同步到菜单、道中、Boss 已有音乐流，并在加载新流后重新应用；静音不停止流的计时。Game 保存灵敏度设置，每帧通过 PlayerInput 的倍率传入 Player，玩家重置不会丢失设置。开局选择页在机体、标准／挑战模式、关卡及符卡练习条目变化时立即保存 `StartSelection`，取消返回也保留最后选择；下次进入及程序重启均恢复对应默认项。难度当前仅开放 Normal。选择记录与本局状态分离，预览、直接开局或重开不会覆盖记录，其他设置保存也保留它；旧配置缺失字段或字段无效时分别采用灵之御札、标准模式、第一张符卡及第一面。

关卡记录使用 `StageHighScores` 的两个模式、六个关卡槽，关卡号从 1 开始，与 `StageId` 的内部编号独立；`kPracticeStages` 同时决定 UI 开放状态和内容工厂编号。标准与挑战分别记录非负 64 位最高分，四种御札共享；普通开局与整关练习在通关/失败结算时更新，符卡练习、预览和调试靶场不计入。较低分不覆盖旧记录，返回菜单、恢复默认设置及重启不清空记录。旧配置的 `best_score` 迁入标准第一面，其他槽不能推断而保持零；完整通关排行榜改用独立的 `koumakyou_scores.dat`，按模式和御札分别保存前十名与八字符名字，旧 `best_score` 不自动迁入缺少身份的完整通关表。

长方体边框和六个表面的空间网格帮助玩家判断深度、速度和朝向。

红雾背景由六面 cubemap 和一个立方体模型绘制。顶点着色器从视图矩阵中去掉平移，只保留旋转，因此玩家移动时背景保持无限远、转动时显示固定世界方向。天空绘制时关闭背面剔除和深度写入，随后恢复这两项状态供敌人和弹幕使用。六面贴图由同一个方向采样函数生成，云、月亮和远山跨面连续。

`position` 始终是三维判定球中心。关卡素材清单为各类敌人和 Boss 定义战斗动画、归一化锚点及世界尺寸；`SpriteRenderer` 用 `DrawAnimatedBillboard` 将原 ANM 当前帧的锚点对齐到 `position`；屏幕上方向由摄像机朝向计算，因此高仰俯角下仍完整显示。敌人与 Boss 的发弹点从判定中心沿瞄准方向向前偏移，调试图层按 F3 显示判定球和发弹点。敌人仅在生成请求到期时创建，出生后立即参与绘制、追踪目标选择与碰撞。

弹体由当前关卡的 `VisualId` 绑定原图集、脚本和颜色偏移；一面保留原始十类敌弹与颜色、10/16/32 帧显现、灵梦玩家弹旋转、激光和道具图像。所有战斗贴图保留连续 Alpha，按相机前向深度合并排序且不写深度，脚本指定普通或加色混合。玩家弹仍叠加本项目 20% tint（Alpha 51），与原 ANM Alpha 相乘。非 ANM 贴图也参加同一透明队列，球体继续使用体积几何；光晕按所在弹体深度排序，避免覆盖前方角色。

## 4 核心数据结构

### 4.1 Bullet

```cpp
struct Bullet {
    bool active;
    bool grazed;
    BulletOwner owner;
    VisualId visual;
    Vector3 position;
    Vector3 velocity;
    Vector3 acceleration;
    Vector3 rotationAxis;
    float radius;
    float age;
    float maxAge;
    float angularVelocity;
    float homingTurnRate;
    float damage;
    Color color;
};
```

弹幕的位置、速度、加速度和旋转轴全部使用 `Vector3`。曲线弹通过 Rodrigues 旋转公式绕任意三维轴旋转速度向量；玩家追踪弹每帧寻找最近的活动目标，并在 `homingTurnRate` 限制下转向。

### 4.2 FixedPool

`FixedPool<Bullet, 8192>` 使用连续定长数组，`BulletSystem` 构造时将整池一次性分配到堆，避免每弹 ANM 状态导致默认线程栈溢出；生成和更新不额外分配槽位内存。行为演员放入 128 槽的 `behavior::ActorPool`；槽位首次使用分配 `Actor`，复用时重置状态并释放旧协程，启动新行为会分配协程帧。`DropSystem` 另用 1024 槽固定池持有 P 点与分数点。各池都记录容量耗尽时的丢弃数量。

### 4.3 Player

`Player` 封装三维位置、yaw、pitch、判定半径、射击、Bomb 和 Power。摄像机不拥有独立位置，避免视觉位置与碰撞位置不同步。Power 初始值和下限均为 8，范围为 8–128，普通 P 点增加 1、大 P 点增加 8，Miss 减少 16（最低 8）；8、16、32、48、64、80、96、128 是火力升级门槛。四机体主副弹数、周期、相位、初始角、速度比例和原始伤害统一读取 `native_combat`，全部主弹每 5 帧生成；Focus 不改变周期。gold 弹由中央模块叠加原始通道像素偏移发射，发射点位于玩家视线前方 1.2 世界单位、屏幕下方 0.6 世界单位处，从开局起显示两个太极圈，使用 player00 的 128/129 脚本反向旋转，中心位于视点前方 1.2、屏幕下方 0.35、左右各 0.78 世界单位。Focus 采用 8/60 秒过渡，以 smoothstep 将左右侧距收拢至各 0.26，释放后展开，反向切换保留当前进度。`Player::OptionPositions()` 同时供太极圈渲染和 cyan 生成使用，副弹必须直接从圈中心出射；`OptionScale()` 让近距离圈尺寸与出生位置等比缩小。两圈作为无碰撞公告板和道具共用透明排序批次，动画游标借用本关卡 Reimu 图集，年龄由玩家游戏时间驱动，暂停冻结、复活重启、关卡卸载前清空；普通弹发射点保持原有布局；准星指向极近目标时，三个模块的前移、下移和侧移量等比缩短，使出射深度不超过目标深度的一半。`Game` 将活动敌人和 Boss 的球形判定快照交给 `Player`，后者在本帧移动和转向后求准星射线相交的最近判定球，按射线进入球面的先后选择目标，以球心沿射线的投影深度建立汇聚平面；没有交点时使用前方 20 世界单位。汇聚中心仍在准星射线上，不吸附偏心目标的球心。各弹从实际模块位置指向汇聚平面上的横向散射落点，修正发射点下移造成的平行弹道偏差，视觉与碰撞使用同一条真实弹道。散射角表示从视点看汇聚落点的横向角，灵札主弹从 Power 8 中央单发变为满级四发、外侧各 7°，梦札满级五发、外侧各 16°；中间档的角度与伤害直接取表，不要求逐档严格递增。青蓝追踪弹从本机新典解析的 `native_combat::ForPower` 读取独立发射周期、相位和原始 20°～80° 张角，按 60 Hz 的 30 帧窗口调度，不随 Focus 加速；分档原值、输入哈希和解析步骤见 [灵梦追踪弹数据对照](REIMU_HOMING_REFERENCE.md)。汇聚平面由视线与横向单位向量构成的正交基计算，保证任意仰俯角下落点围绕准星对称且弹速一致；gold 按原始通道角度与偏移发射，零角通道经过准星；灵札满级含两个不同出射位置的零角通道，不保证每颗散射弹命中；直射弹在生成时锁定方向，后续转动视角不改变已出射弹道；cyan 各通道在到期帧同时从左右模块各发一颗，出射后继续使用项目现有最近目标追踪规则；Power 切档保留当前相位，点射完成已启动的 30 帧窗口，禁火和复活取消窗口，小数帧累积并逐逻辑帧补发以保持不同帧率下的弹量一致。`DropSystem` 持有两类道具共用的 1024 槽对象池，按敌人静态结果表的相对权重抽取一次 P 点与分数点数量，将道具在敌人死亡位置附近错开生成。道具生成时以 4 单位/秒向世界 +Z 上抛，沿 -Z 以 8 单位/秒² 持续加速，0.5 秒后在比生成点高 1 单位处回落，下落速度达到 2.5 单位/秒后保持匀速；加速段和匀速段按限速时刻拆分并精确积分，保证不同帧长下位移一致；玩家进入战场 +Z 端 2/5 区域（z ≥ 2.3）时，所有活动道具立即中断上抛或下落，记录追踪状态并以 20 单位/秒向玩家移动；该状态在玩家离开后仍保留，新生成道具需再次满足触发条件，距离玩家中心小于约 0.892857143 世界单位后拾取；未进入追踪状态的道具沿 −Z 下落至场地后边界之外（z < −11.5）时消失，追踪中的道具持续到拾取或清场。`Game` 应用拾取奖励；当前分数点固定增加 1000 分，Boss 暂沿用固定大 P 点。道具使用当前关卡提供的 `power_point` 与 `score_point` 外观，交给 `SpriteRenderer` 与敌人和 Boss 一起绘制。Debug 射击测试停用时间轴并保留固定靶怪，用 F5/F6 调整 Power。

梦之御札共用副弹的 60 Hz、30 帧窗口调度器，从 `native_combat::ForPower` 按 Power 读取原始侧针周期、相位、圈内 X 偏移和原始伤害。侧针不追踪，以太极圈原始 36 像素直径为基准还原多束偏移和上移 16 像素，Focus 与近距离缩放沿用圈中心及 `OptionScale()`；具体时序与三维换算见 [梦之御札侧针对照](REIMU_NEEDLE_REFERENCE.md)。主弹与侧针取同一原始火力表，废除旧的自定义弹数、1.5° 散射、伤害 3.3 与 Focus 冷却差异。关卡通过 `PlayerNeedleVisual()` 单独提供侧针脚本 66，不替换中央符卡素材。

魔理沙的 `MagicMissile` / `IllusionLaser` 读取统一的 `native_combat::ForPower`，主副弹统一按原始 30 帧窗口调度；导弹按 60 Hz 原始加速度积分，命中后切换 20 帧的爆破，激光按每副机独立的绝对游戏时间冷却，不能把 120～330 帧槽时间当成发射周期。`PlayerShotVisuals` 由关卡提供四级导弹、三级激光和对应爆破素材，`PlayerOptionVisual(side, shot)` 按实际机体选择灵梦太极圈或魔理沙星形物件。持续弹使用 `damagePerSecond` 与每次更新的有效秒数，胶囊判定支持激光穿透，多目标结算完成后清空本次秒数；跨过寿命终点时保留末段伤害再回收，不能在每个敌人处直接销毁光束。原值、生命周期和换算见 [魔理沙御札对照](MARISA_SHOTS_REFERENCE.md)。一面使用实际角色的对白与六种表情；符卡练习将四组合拆为角色、角色内御札，成绩由实际 `Player::Shot()` 编号写入。

四御札 Bomb 由 `PlayerBombEffect` 统一持有攻击、清弹与世界几何，`BombDefinition` 映射原始脚本、时长、保护和回调来源。`UpdatePlayerBomb` 在敌弹运动后、玩家碰撞前逐个 60 Hz 帧调用 `ResolvePlayerBombFrame`，按 region 合并命中，再经 `ResolveDamage` 处理 70 上限及符卡整数 ÷3，并将原始命中量反馈给封印光球。新符卡排除旧 Bomb 伤害，击破与掉落使用已有正式入口。`BombVolume` 为球、轴对齐符阵薄盒和有限圆台，伤害、清弹和 `DrawBombGeometry` 读取同一份几何。64 颗星飞向 4×4×4 网格格心，保留八个伤害通道，体积覆盖保守下界超过 81.4%；封魔阵前 60 帧无伤蓄力，随后六面从施放点向外扩展，横向尺寸和厚度同步增长；单根巨束从角色位置出射，通过八角投影确定束宽和长度以覆盖正向半场，身后保留盲区；外部具有 16 边圆截面、淡外缘、张开的内芯和发光密度，主视角仅绘制一组沿束轴流动的内部光线，保留中央视野；其轴向/演员深度切片加入 `SpriteRenderer` 统一透明队列。实例可在无 ANM 时运行攻击，不占普通弹池；十五个原生脚本仍由关卡持有。释放吸取所有现有道具，恋札期间三轴移速 0.3 倍；暂停不推进，退出、重开、受击和结算清空攻击、资源借用及声音。详情见 [四 Bomb 对照](PLAYER_BOMBS_REFERENCE.md)。

### 4.4 行为演员与 Boss

`behavior::Actor` 是直接运行的具体组件，同一对象保存世界位置、生命、判定半径、分数、掉落、动画游标和 `motion/skills` 状态。`Activate(Spawn)` 校验并复制配置，确定随机出生位置，启动 `Follow(Pattern)`；默认以 120 Hz 推进移动、技能和动画（每步 1/120 秒），编排和阶段时钟仍以 60 Hz 内容帧记录，每步增加 0.5 帧，实际进入世界 X/Z 回收边界后再允许越界回收。时间轴显式列出原始帧、世界位置、镜像、数值及固定种子；运动状态、插值、发射偏移与边界均使用世界坐标，速度/加速度使用世界单位每秒/每秒平方，角速度使用弧度/秒。`Position()` 直接返回运动位置，不再经过像素投影；原始坐标换算只留在测试基准。`ReferenceScript` 只在测试目录作为独立差分基准，对照演员显式选择 `behavior::UpdateRate::Hz60`；生产演员池与 Boss 使用默认的 `Hz120`，同一配置的技能时刻和插值时长不因更新频率改变。旧敌人基类、子类、出生参数 variant 和小怪工厂已移除。

八个按角色命名的 Boss 子类位于 `src/gameplay/bosses`，各自的 `StartBoss(StartConfig)` 接受可复制启动配方。角色内部 `ResolveSkill` 绑定技能血量、时限、元数据，内嵌 `Behaviors` 实现所有角色专属行为；各关 `boss_config.*` 仅声明每阶段技能组合、伤害/超时去向、显式血条比例与颜色、对白入口及退场；`StartBoss` 事件直接借用静态命名战斗定义。五、六面的咲夜共用 `SakuyaBoss`。`RumiaBoss` 通过不同配方执行道中 `Midboss` 和关底 `FirstNonspell` 等命名阶段。受保护准备期不接受射击/Bomb 伤害；退场行为执行完毕才通知事件结束。Normal 道中无符卡；关底为普通攻击、Night Bird、普通攻击、Demarcation。HP 与阶段阈值使用统一目录中的原始点数，与自机伤害保持相同量纲。详细时序与数据来源见 `STAGE1_REFERENCE.md`。

所有敌人和 Boss 持有 `ActorPresentation`：小怪入场 0.25 秒，Boss 入场 0.6 秒，以淡入、从 65% 到完整尺寸的缩放显示；原始 ANM 外观不叠加程序光环。视觉时钟不推迟出怪、碰撞或攻击。普通越界小怪按当前外向速度预测到达战场表面的剩余时间，提前 0.25 秒淡出，仍在原来的场外 2 单位处回收；暗色妖精按已知返回终点提前淡出。首次移动可能包含轨道初始偏移，不用于速度外推；边界预测只在本帧有效，转向后可恢复显示，不能把预测永久锁定为退场。仅已知返回终点的退场进度不可逆。Boss 换阶段不重放入场。

`ActorEffectSystem` 使用 512 槽固定池保存退场位置、外观 ID、判定半径与最后的视觉采样，不保存角色指针或 GPU 资源。自然退场与清场收缩淡出，小怪为 0.25 秒、Boss 为 0.5 秒；原始外观击破时选择独立爆散 ANM，由删除指令结束，ECL 100 保留三种爆散选择；非 ANM 外观仍使用闪光、扩散环和三维球面粒子，小怪为 0.3 秒、Boss 为 0.8 秒。快照不能被索敌或碰撞，战斗对象立即失活并允许复用槽位。小怪仅实际击破时给一次分数和掉落，清场不奖励；Boss 按击破/超时回调推进，奖励与脚本道具事件分开结算。暂停冻结活动角色与快照，收尾期间暂停后继续收尾；效果池满只丢弃视觉，不能阻止结算。关卡资源必须覆盖全部快照的绘制寿命。

原始角色、过渡角色与退场快照使用默认 shader 保留连续透明度，与原始敌弹和玩家透明弹共同从远到近绘制且不写深度。普通 PNG 同样保留连续 Alpha；程序光环和三维粒子随演员的透明绘制项提交。掉落物和激光参加同一队列；长激光按精灵深度平面切分，沿整束裁分 UV，不在切分处重复贴图。排序计入 ANM 局部变换，同深度采用稳定顺序。透明批次提交后才能恢复深度写入和剔除，辅助网格禁止写入深度。退场快照持有最后一帧值，击破动画游标只借用关卡档案，关卡卸载前必须清空。

### 4.5 StageEvent

关卡由只读事件表驱动。`StageEvent` 将 `delay`、可选 `atFrame`、`id` 和 `afterEndOf` 与带参 `StageAction` 分开保存，动作是 `SpawnActors`、`StartBoss`、`StartDialogue`、`ShowMessage` 的 `std::variant`。`StageContent::HandleEvent` 使用访问器将一次动作分派给游戏总控；新增动作须同步扩展校验与执行访问器。

`atFrame` 使用开局起算的非负 60 Hz 帧，不能与 `afterEndOf` 同用。未设置时，`delay` 无依赖时相对上一事件的实际开始时刻；首个事件相对开局；有 `afterEndOf` 时相对指定事件的实际结束时刻。依赖必须指向事件表内更早的唯一 ID。Boss 与对话必须带 ID，结束时通过 `EndEvent` 通知调度器；提示即时结束。所有延迟和持续时间使用非负有限秒数。

`SpawnActors` 直接持有敌人配置，连续出怪数量默认 1，间隔默认 0.5 秒。数量至少为 1，间隔可为零；首只立即生成，后续第 i 只相对本批实际开始时刻延迟 i × interval。各次生成复用配置但创建独立实例，同一批次不隐式改变位置或轨迹。`StageDirector` 在运行时保存已生成数量，将每次回调规范为 count=1，事件表不被修改；跨帧时补发全部到期请求，时间以批次开始计算而不逐次累积误差。最后一次请求实际发出时记录批次结束，与敌人死亡或池满丢弃无关；整批结束不能用 `EndEvent` 提前报告。多个批次可并行，后续事件默认仍相对上一事件开始，等待整批结束需使用 `afterEndOf`。Reset 清除批次进度；Boss 入场与对话开始用 `CancelEnemySpawns` 取消已启动批次的剩余请求并记录取消时刻，尚未启动的事件仍由时间轴控制。道中及关底 Boss 入场保留现存小怪、敌我弹幕、道具和退场效果，各对象继续正常更新；对话开始仍清除小怪与敌弹。

Stage1 使用 222 次独立出生请求，逐只保留原横坐标和镜像航线。道中 Boss 存在时跳过到期请求，但时钟继续走；不是退场后再计算后半段延迟。战前对话结束触发关底，关底退场后进入战后独白，独白结束触发 `StageClear` 奖励明细；普通开局一至五面关闭后继续下一关；完整通过六面后收尾进入结局，再进入成绩选存与命名；整关练习关闭奖励明细后安全返回 Stage 页。

## 5 三维弹幕算法（通用/调试图案）

实际一面的路径和图案已提炼为世界坐标下的 `movement`、`skill` 和命名行为，沿 Z 从远端入场，并添加整轮 Y 高度坡度；延迟转向绕 Y 轴旋转。`ReferenceScript` 只用于 60 Hz 独立测试，数据到代码的转写方法见 [Stage 移植方法](STAGE_PORTING_METHOD.md)。以下通用函数仍供自定义演员和测试使用。

### 5.1 球面星状散射

二维星状散射通常在圆周上均匀取角。三维版本需要在单位球面上均匀取方向。本项目采用 Fibonacci 球面：

```text
t = (i + 0.5) / n
y = 1 - 2t
r = sqrt(1 - y²)
phi = i * goldenAngle + rotation
direction = (r cos(phi), y, r sin(phi))
```

这种分布不会像经纬度网格一样在球体两极聚集。`pattern::ForEachSphereDirection` 提供方向，具体敌人的技能函数决定弹体参数并调用 `BulletSystem::Spawn`。当前只有强化敌人的技能使用球面散射。

### 5.2 三维锥形瞄准弹

首先计算敌人到玩家的单位方向，再构造与该方向垂直的 right/up 正交基。`pattern::ForEachConeDirection` 只计算方向；通用调试演员的技能函数负责生成弹体。弹幕按多个圆环分布在锥面内，因此玩家需要同时沿水平、垂直和纵深方向躲避。

### 5.3 三维碰撞与擦弹

所有判定均为球体碰撞，比较三维距离平方：

```text
(dx² + dy² + dz²) <= (r1 + r2)²
```

玩家只有一个判定球，因此敌弹检测为 O(B)。玩家弹和敌人数量较少，首版采用 O(Bp * E) 检测。

本体接触由 `Player::ContactEnemyBody` 比较新典玩家世界半径约 0.055803571 与敌方 `hitRadius` 的 2/3，查询不改变敌方状态或自行扣残机。`behavior::Actor::CanContactPlayer` / `Boss::CanContactPlayer` 排除失活和零生命对象，与 `CanTakeDamage` 独立；露米娅覆盖该接口关闭退场脚本期间的本体伤害。视觉入退场不修改判定球，对话阶段不检查本体。`ResolveCollisions` 将敌弹、普通敌人和 Boss 本体的接触合并后调用一次 `HandlePlayerHit`，沿用复活/Bomb/Debug 无敌、清弹、Miss 计数及资源扣除；本体不产生擦弹、撞击伤害或击破掉落。退场效果快照不参与查询。

## 6 游戏流程

```text
主菜单
  -> 三维道中连续出怪
  -> 蓝色与紫色妖精波次
  -> 道中露米娅普通攻击
  -> 后半段妖精波次
  -> 灵梦与露米娅对话
  -> 关底露米娅普通攻击
  -> 夜符 Night Bird
  -> 第二段普通攻击
  -> 暗符 Demarcation
  -> 战后独白
  -> 关卡奖励明细（10 秒或确认）
  -> 普通开局继续二至六面 / 整关练习返回关卡选择
  -> 完整六关：收尾 -> 结局加载与播放（不含制作人员）
  -> 最高分选存 -> 八字符命名 -> 对应前十排行榜
```

`StageClearSummary` 在战后对话结束时固定关卡号、Power、Graze 和 Point Item，沿用 Normal 的 `(Stage×1000 + Power×100 + Graze×10)×Point Item` 奖励并只加分一次，同时保存有效整关最高分。`RunState::StageClear` 的 10 秒 UI 时钟独立于时间轴和对话，退场效果可继续消散；确认仅关闭本层，下一帧才继续收尾，不能穿透到后续菜单。暂停可冻结该倒计时，恢复计分面板时保持光标可见。整关练习关闭面板后经过安全收尾返回关卡选择，不进入普通通关操作菜单。`ReturnToPracticeStage` 复用离开关卡的清理顺序，释放效果、演员、弹幕、道具及关卡素材后重建 Stage 页，保留本局模式、御札和关卡，并跳过首页背景以免闪屏。整关练习暂停列表在原有三项之后增加返回关卡选择，导航、命中与底板高度均读取同一列表；普通开局暂停仍为三项；符卡练习暂停增加返回符卡选择，结束页保留返回选卡／保存 Replay／重试，Replay 尚未实现并置灰。

## 7 当前限制

- 长方体战场与红雾天空盒由程序生成；对话灵梦与露米娅使用现代重绘，战斗角色、弹幕与道具使用原始 DDS/ANM。
- Normal 出生/移动/攻击数据已直接导入；已开放两位角色、四御札与一至六面，其他难度和 Extra 尚未开放；其原始战斗素材已经登记到公共目录。
- 原逐敌掉落字段、脚本散落与音效已接入；玩家火力、拾取运动、分数与随机序列仍采用本项目三维约定。中文原文对话已接入，现代重绘立绘按台词恢复双方最近一次表情；玩家 6 个、Boss 4 个差分由关卡映射到 VisualId。dialogueCrop 为仅对话使用的归一化裁剪区域，符卡由 SpellPortraitVisual 选择完整图，世界角色独立使用原始露米娅战斗动画。
- 当前使用球形碰撞，不考虑模型网格的精确碰撞。
- 关卡事件编译在程序中，后续可迁移到 JSON 和可视化编辑器。
- 尚未加入雷达；当前通过长方体边框、表面网格和近弹警告辅助空间判断。

原始生命与伤害目录位于 `gameplay/data/native_combat.*`，编译时持有七关 3598 条生命记录、四机体 193 条通道。源码记录输入哈希、ECL 偏移、掩码、Normal 指令索引和 PE RVA；运行时不要求安装原作或执行 Python。`Stage(1..7)` 独立于可玩关卡目录：一面为 Playable，其余为 DataOnly，不能据此开放选择。一面时间轴出生 HP 由测试逐条核对目录原值，Boss 阶段生命与 HUD 直接读取原始点数；已移除恒为 1 的 `kReferenceHealthUnit` 接口。未知默认 HP、寄存器生命须由未来关卡提供上下文，`RequireLiteral` 对此拒绝返回假常量。

`ResolveDamage` 是统一伤害入口，`DamageContext` 提供原始接触伤害、机体、来源 RVA、目标身份、保护/符卡状态、Bomb 使用状态及有效秒数。`StageContent::DamageRules()` 可覆盖规则；未处理返回 nullopt，默认结果区分 BaseOnly、Fallback 与 NativeRule。Bomb 必须传入同一逻辑帧的通道合计，按本机新典每帧 70 上限、符卡整数 ÷3（最低 1）和新符卡旧 Bomb 保护处理，不再使用固定 550/875 伤害。普通弹在 Bomb 期间按原始接触伤害 ÷3（最低 1）；普通弹对 Boss 的 0.8/符卡 ÷7 回退和普通弹/Bomb 联合上限尚未作为完整原引擎结算重构。普通弹仍用三维球形判定，原表矩形尺寸、音效和坐标完整保留。详情见 [原始战斗数据接入](NATIVE_COMBAT_DATA.md)。

BGM 使用独立的 `audio::BgmPlayer`，加载 FLAC 与旁路循环元数据后预解码为 16 bit PCM；音频回调在单个缓冲内按原作区间回绕，前奏只播放一次。所有音乐槽及回放定位共用此规则，音频供样不依赖显示更新。来源、单位、EOF 边界和验证入口见 [BGM 原作循环](BGM_LOOP_REFERENCE.md)。
