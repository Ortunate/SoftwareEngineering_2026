# 四种御札的 Bomb 演出

以本机新典 `th06nc.exe`、`player00/player01.anm`、原始高清 DDS 和中文翻译核对。EXE SHA-256 为 `48630a42a2eb6762d0db2a7e0d151203efbe67220fef7d2f9d0d51857928ac82`。公开 [TH06 BombData.cpp 还原工程](https://github.com/GensokyoClub/th06/blob/master/src/BombData.cpp)用于辅助阅读，数值以本机新典为准：例如魔札的保护时间是 **310 帧**，不能照搬标准版的 300。

回调表 RVA 为 `0x426eb0`，每项是两个 64 位回调地址。以下脚本编号属于各自 ANM，不是全局编号；原加载基址为 1056。

| 御札 | Bomb 原名 | ANM / 脚本 | 演出帧数 | 保护帧数 | 计算 / 绘制 RVA |
|---|---|---|---:|---:|---|
| 灵之御札 | 灵符「梦想封印」 | player00 / 133～136 | 300 | 360 | d8d0 / e0f0 |
| 梦之御札 | 梦符「封魔阵」 | player00 / 137～140 | 140 | 200 | e280 / e860 |
| 魔之御札 | 魔符「Stardust Reverie」 | player01 / 5～7 | 250 | 310 | e9a0 / ed80 |
| 恋之御札 | 恋符「Master Spark」 | player01 / 8～11 | 300 | 360 | ef20 / f310 |

所有时间为 60 Hz 游戏帧。`BombDefinition` 是四种御札共用的规格，玩家库存和冷却、效果实例与关卡素材绑定都读取此规格。释放一次只消耗一枚 Bomb，同一场演出不能重复启动；保护期覆盖演出及之后的恢复时间。

## 原始攻击与结算

本机执行代码验证了以下常量与分支，不由静态自机火力表推断。`tools/inspect_native_bombs.py` 会校验 EXE 哈希及 18 处机器指令，导出参数和原始指令证据。

| Bomb | 原始攻击 | 逻辑帧条件 | 原始区域全尺寸 |
|---|---|---|---|
| 梦想封印 | 追踪接触每帧 8；累计原始接触伤害 ≥100 后，下帧爆破 200 | 光球出生至爆破；最迟 270 帧爆破，爆破只有触发帧造成伤害 | 飞行 48×48，爆破 256×256 |
| 封魔阵 | 四个通道各 8，移动十字扫场 | `frame>0 && frame%2!=0`；偶数帧仍清弹 | 62×448 / 384×62 |
| Stardust Reverie | 八条径向路径各 8 | `frame>0 && frame%3!=0` | 128×128 |
| Master Spark | 前方区域 12，四层图像共用一个通道 | `frame>0 && frame%4!=0` | 宽 384，高为自机至场地前端的距离 |

魔札和恋札的条件是**排除整除帧**，并非每 3/4 帧打一发。`CalcDamageToEnemy` RVA `0x6b420` 累加命中通道并累计封印光球原始伤害。敌人结算在 `0x393dd` 将同帧伤害截到 70，积分为 `floor(capped/5)*10`；符卡已使用 Bomb 时按整数 `/3`、非零最低 1 结算，符卡开始前释放的旧 Bomb 不得继续伤害新符卡。当前 Bomb 入口先合并通道再应用这些规则，单个光球的 200 爆破实际最多扣 70，不能每张纹理扣 200 或将爆破持续 30 帧计算。

释放时没有全场固定 550/875 伤害，也没有所有 Bomb 通用的瞬间全屏清弹。封印有初始 256×256 保护区；后续清弹使用各自攻击实体，额外保留原作擦弹检查中的 20 逻辑像素容差。所有 Bomb 都立即吸取当时已存在的道具；之后生成的道具照常遵守自动吸取线。恋札演出期间三轴移速为 0.3 倍，跨结束时刻的长帧只缩放有效时间。

每个 60 Hz 帧都立即调用战斗结算再推进下一帧，30/60/144 FPS 不丢攻击、清弹或爆破反馈；暂停不结算，同一帧重复进入碰撞入口不会再扣血。缺少动画档案仍可运行攻击模拟，Bomb 不依赖普通弹池空槽。敌人击破、掉落、Boss 生命回调与捕获失败都走现有正式入口。

## 三维几何与演出

- 梦想封印：在 **80、96、112、128、144、160、176** 帧释放七颗四色光球，使用速度/8 的三维吸引及 1～10 像素/帧限速追踪当前可受伤目标。只有真实累计命中或第 270 帧触发爆破，不再按视觉接近距离引爆。球形光晕和爆破体积随实例运动，三张世界固定的原生纹理截面包覆每颗球。
- 封魔阵：以**施放点为中心向外扩展**，六面法阵的中心位置、横向尺寸与厚度同步增长，最终到达 20×20×23 战场的六个边界；施放后移动或转头不改变已释放法阵。前 60 帧仅蓄力，不造成伤害或清弹，也不触发全屏闪白；第 61～139 帧外扩期间仅触碰法阵的目标受伤，奇数帧各通道 8，偶数帧仅清弹。Z 向两面与 X 向对应通道取并集，最多仍四份伤害。初始法阵仅在施放点附近，不使用贯穿全场的初始截面，远处目标随外扩波前到达后才受伤。
- Stardust Reverie：增加为 **64 颗星**，从施放点飞向战场 4×4×4 等体积网格的格心，180 帧到达后停留至演出结束。每颗保留原始 64 像素攻击半径、8 点伤害和排除整除帧的节奏，以 `i%8` 合并为八个伤害通道，增加空间覆盖不按星数直接乘伤害。本体为六向立体星芒和三张原生贴图截面，另有一个较小拖影；拖影不造成伤害。延长原生脚本的末尾采样并在最后 30 帧淡出，避免有攻击却无图像。
- Master Spark：从**角色位置沿视线发出一根宽束激光**，覆盖前方整个场地，身后保留盲区。每次更新将场地八角投影至束轴，以最大径向距离加 0.5 世界单位作为近端半径，远端再扩大 6%；长度至少 40，超过场地最大正向投影 1 单位，因此不只覆盖远端，近处两侧和上下边角也在攻击内。四种原色与贴图完全同轴，共用唯一伤害体积。外部视角显示较淡的完整外缘和逐渐张开的高亮内芯，内芯从角色位置附近发出。第一视角绘制真实束轴内部的 12 道纵向流光，具有柔和外晕、细芯、运动脉冲和远端淡出；不绘制封闭截面、圆环或遮满视野的白色盘面，中央保留目标视野。内部只绘制一次，避免四层 ANM 叠加过曝；全部攻击仍由同一个宽束体积结算。

魔札在到达阶段的实际攻击球联合覆盖全场约 86.5%；回归用 128³ 个等体积小盒，仅计入被真实攻击球完整包含的小盒，验证保守下界 **81.42% > 80%**。该比例不计敌人半径、清弹容差、拖影或飞行期间扫过的额外空间；从场地八个角落施放并转动视线，也必须抵达相同格心。因此一次施放的覆盖率至少达到该下界。

伤害数值和通道合并读取原始规则；梦札增加无伤蓄力期、魔札改为 64 颗网格星群以及恋札改为前方全场宽束，是按三维玩法需求调整的攻击布局，不能声称这些调整存在于二维原版。攻击尺度统一为 `20/384` 世界单位/逻辑像素，`BombVolume` 同时供伤害、清弹与渲染读取。光球和星群保留原生纹理柔边，其大小不代替命中体积。实体顶点为世界坐标；普通自机弹的 Alpha 51 不应用到 Bomb。镜头进入光球或星体附近时只衰减近眼曝光，不改变攻击半径与路径。

背景在 60 帧内渐入压暗，最后 60 帧恢复；通常最大 Alpha 为 176，恋札为保留束内场景辨识降至 96；压暗先于透明战斗对象及加色 Bomb 绘制。透明排序统一处理敌人、道具、弹幕和 Bomb。巨束使用 12 个轴向区间并按演员深度继续切分，UV 沿整束连续；小弹与小道具使用轴向区间排序，避免密集弹幕或星点把同轴网格切成数万份。内部亮度按真实区间长度加权，额外排序切片不会重复增强亮度。压暗显式保存和恢复投影与相机 view。三维扩展使用加色密度和光壳权重适配沿光轴观看，不再重复绘制同一张相机朝向的激光带。

短暂的自机宣告继续使用现有重绘立绘；名称使用新典中文翻译并保持至演出结束。暂停冻结时钟，绘制不推进动画。演出不占用弹幕池，不产生额外碰撞或掉落；死亡、重开、结果页及卸载关卡前清空 ANM 借用。

## 音效与保留边界

梦想封印的逐颗释放使用原音效 13（已有 `gun00`），爆破使用 15（与已有 `tan00` 同波形）；封魔阵与 Stardust Reverie 使用 6（已有 `power1`），Master Spark 使用 19（新接入 `nep00.wav`）。同一更新内的同编号事件只播放一次，与原声音队列避免重复的行为一致。

新增 `assets/runtime/common/se/bomb_master.wav` 逐字节来自本机 IN 包的 `nep00.wav`，SHA-256 为 `f5bdbc92afefd4bec217f2df04bb35239f9ce9de51e10dccef6013c025c38b82`。长音效随暂停冻结，只恢复实际暂停的缓冲；退出或取消演出时停止，避免菜单中残留 Master Spark 声音。

四种 Bomb 的区域伤害、接触累计、持续清弹、道具吸取、恋札减速、冷却与保护均已接入。`ResolveDamage` 的 Bomb 分支返回 `NativeRule`，仍允许关卡提供方覆盖。普通弹在 Bomb 期间按原始接触帧伤害 `/3`，最低 1；普通弹对 Boss 的既有 0.8、符卡 `/7` 回退未在本项扩展为完整原引擎伤害模拟，普通弹与 Bomb 的同帧联合上限也未重做。屏幕震动尚未加入，避免强制晃动第一人称视角。

## 复核

```bash
python3 -B tools/inspect_native_bombs.py /本机安装目录/th06nc.exe --assets assets/runtime --output /tmp/native-bombs.json
cmake --build build-debug --target koumakyou koumakyou_tests koumakyou_lifecycle_tests koumakyou_sprite_overlap_tests
ctest --test-dir build-debug --output-on-failure
build-debug/koumakyou_lifecycle_tests /tmp/player-bomb --bomb-only
build-debug/koumakyou_lifecycle_tests /tmp/player-bomb --bomb-audio-only # 初始化音频设备，但输出强制静音
build-debug/koumakyou_sprite_overlap_tests /tmp/player-bomb-overlap
```

审阅工具只读 PE 和 ANM，不依赖反汇编器。核心测试核对 30/60/144 FPS 下的完整帧伤害与爆破帧序、圆台侧面/端面/背后排除、横穿胶囊、三轴法阵由施放点外扩及 125 个场地采样点覆盖、魔札 64 个攻击球的体积覆盖下界和八角释放一致性，以及恋札从中心/八角出发、向水平/竖直/斜向开火时的前半场覆盖与身后盲区、恋札减速恢复。集成测试使用真实 Game 验证梦札蓄力无伤与法阵接触扣血、恋札主视角中心无遮挡、重复结算防护、范围外/无敌目标、敌方激光取消、玩家弹保留、击破只掉落一次、累计封印爆破和新符卡保护；还导出四种主视角、侧视角和横竖屏画面，并校验暂停、压暗矩阵及退出清理。
