# 一面子程序到带参行为的映射

本次重构以项目重构前的 Normal 行为为一致性基准，涵盖实际关卡使用的五种道中敌人、道中露米娅、关底四阶段及退场。出生、HP、镜像、随机种子、掉落、动画和原有三维适配保持原约定。Hard/Lunatic 的道中符卡及新典自己的符卡练习入口不在当前可玩范围内，本次没有扩大难度或入口范围。

## 运行结构

`timeline.cpp` 直接定义固定的 `std::array<StageEvent,226>`，显式列出 222 次杂鱼出生和 4 个 Boss/对话事件；不通过 lambda、循环或原始数值目录构建时间轴。每次出生的帧号、坐标、HP、分数、掉落、镜像、随机横坐标标记、种子和外观均直接写在表中，五种命名行为配方以 `behaviors.hpp` 中的 `inline constexpr` 常量共享复用，生产代码直接按名称引用。`Spawn` 只封装参数并转换坐标。每个参数对象按值保存 `pattern.movement` 与 `pattern.skill`；`SpawnActors` 直接携带 `behavior::Spawn`，由 `ActorPool::Spawn` 启动独立 `behavior::Actor`；没有小怪工厂或用于运行时选择路径的 `sub` 字段。

- `gameplay/actors/movement.*`：极坐标运动、定时转弯、速度/加速度变更、线性/加减速插值和边界。
- `gameplay/actors/skill.*`：固定/瞄准扇形、固定/瞄准环形、速度层、显现、发射加速、延迟转向/重新瞄准和固定瞄准光束。
- `gameplay/actors/behavior.*`：`Pattern`/`Spawn` 配置、`ActorPool`、60 Hz 行为时钟和局部子行为调用；同一 `Actor` 保存战斗、动画、入场/回收状态，不认识 ECL 操作码。
- `stages/stage1/behaviors.*`：道中配方及露米娅命名阶段，复用移动和技能组件。
- `tests/reference_script.*` 与 `tests/reference_program.hpp`：保留重构前解释器和指令，只编译进测试；生产引擎和游戏不再链接它。

Sub10～12 是道中 Moonlight Ray 及其辅助流程，Normal 道中不进入。Sub13 是新典对话期间的 Boss 入场等待体；本项目原来由独立对话演出控制该段，战斗从 Sub14 对应阶段开始。Sub32～37 是新典练习准备/退出入口，本项目原来通过自己的练习生命周期进入夜符/暗符。这些范围继续作为原始对照数据保留，没有伪装成此次新增可玩内容。

非符扫描把原子程序内的局部跳时和计数循环归一为实际发射时点：两种扫描方向都从进入后第 2 帧开始，每隔 2 帧发射。速度和角度保持逐次浮点加法，避免改用乘法公式改变舍入。夜符和暗符同样以参数循环表达扫描，不再保留寄存器或指令跳转标签。

## 时序不变量

1. 每个逻辑帧先应用上一帧速度，再执行当前移动/技能编排，最后计算下一帧速度。不能交换该顺序。
2. 子行为有独立局部时钟，调用期间父行为时钟冻结；子行为返回后父行为在同一逻辑帧继续。阶段总计时与动画时钟独立推进。
3. `Update` 跨显示帧补算固定 60 Hz；暂停不推进；阶段回调发生后保留未消费逻辑时间。重开和销毁会释放全部挂起行为。
4. 镜像只反转 X 位移。原 Y 向下映射世界 -Z，原 Z 映射世界 -Y。单轮弹幕锁定玩家高度坡度，保留既有三维投影。
5. 角色的随机数状态独立；读取次数和顺序必须保持。随机横坐标仍在出生时求值一次。
6. 道中出生 HP 在事件表中显式给出，并与统一原始目录回归核对；Boss 阶段生命/阈值/超时仍查询统一目录，命名阶段回调与原始回调关系由差分测试核对。
7. 清弹只重置原有 rank 修正，不清除运动或后续技能上下文；已经生成的弹拥有自己的运动参数副本。
8. 插值的位移计算与坐标相加保留原来的浮点求值边界，避免融合乘加带来轨迹漂移。

## StageEvent 衔接

道中出生仍使用原始 `atFrame`，道中 Boss 在 1882 帧开始，战斗期间不暂停关卡时间轴，Boss 存在时到期的杂鱼请求由游戏跳过。5092 帧进入战前对话；关底 Boss 使用 `afterEndOf` 等待该对话结束；战后独白再依赖关底 Boss 结束。事件 ID 和异步完成规则保持原样。随机种子为保持旧行为而固定为原值，之后插入其他事件不会隐式改变既有敌人的随机状态。原始目录更新后需要人工同步事件表；差分检查会报告出生参数或时序不一致。

扩展敌人时可直接构造 `behavior::Spawn`，修改 `pattern.movement`、`pattern.skill` 和 `visual`，再放进 `SpawnActors`；不必增加子程序编号或修改解释器。配置校验会拒绝非有限值、错误关键帧顺序、超出寿命的技能及非法弹数/外观。

## 验证

`tests/behavior_tests.cpp` 直接运行重构前解释器和新实现，比较第一次不一致的帧，期望值不从新配方生成：

- 覆盖当前 Normal 可达的 28 个原子程序，包括所有非符随机分支和符卡辅助程序；覆盖率由旧解释器独立记录。
- 使用 30/60/144 FPS、rank 10/16/32、三个随机种子、镜像和动态三维瞄准目标，并插入零时间更新。
- 比较逐帧位置、HP、免伤、动画编号/重启次数/年龄、音效、掉落、回调、阶段时间，以及实际弹池槽序和所有敌弹运动/光束参数。
- 对 222 条真实出生记录逐条检查时间轴参数、行为实例、随机出生坐标、运动、技能及自然退场。
- 连续经过伤害阈值或超时驱动的关底阶段，验证跨阶段保留状态、清弹、准备期及退场。
- 独立组合自定义路径和技能，验证非法配置拒绝，以及重开/销毁时父子挂起行为的资源释放。

离散状态逐项精确比较，浮点运动参数允许绝对误差不超过 `1e-5`。本机 macOS Debug 构建通过，CTest 2/2 通过；完整图形集成通过，包含 30/60/120/240 FPS Boss 切换和 311.05 秒无攻击整关结算。

运行方式：

```bash
cmake --build build-debug --target koumakyou koumakyou_tests koumakyou_lifecycle_tests -j 6
ctest --test-dir build-debug --output-on-failure
./build-debug/koumakyou_lifecycle_tests /tmp/stage1-behavior-lifecycle
```

这里的一致性指相对于重构前项目行为的回归，原项目与新典原生引擎之间既有的三维适配、随机序列差别和未实现演出仍按 `STAGE1_REFERENCE.md` 的说明保留。

旧 `Enemy`、四个敌人子类、`EnemyPool`、`EnemySpec`、关卡专用出生参数和小怪工厂已删除。原来只验证旧类的曲线与技能测试同步移除，入场、碰撞、掉落、池复用和图形遮挡测试直接使用行为演员；原始 222 条出生及 28 个 Normal 子程序差分继续保留。
